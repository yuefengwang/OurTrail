# 限制与路线图

> 这份文件回答两件事：**现在做不到什么**（附原因与剩余风险），以及**下一步先做什么**。
> 每条限制都指到能复核的文件；没有"将来会有"的承诺，也没有成功率估算。

## 1. 限制分层

问题可能出在四层，处理方式完全不同——先把层分清，再谈能不能修：

| 层 | 含义 | 例子 | 处理方式 |
|---|---|---|---|
| **仪器** | 适配器量不到这个量 | 微信侧没有 DOM/CSSOM（`App.CDPEnable unimplemented`）；截图缩放 0.78 | 声明进 `LIMITATIONS.md`，判定降为 `UNVERIFIED`，不得推断成 PASS |
| **判定** | 量到了，但判据不够细 | 20px 以上字重变化漏报；`acceptedDifferences` 只能按类别接受 | 改判据要先过实验 A/B（改容差不得改变实验读数） |
| **流程** | 步骤有，但没在真实项目上执行 | OurTrail 实现层修复 `BLOCKED`（授权）；小程序侧成组实验 `NOT_RUN` | 如实标状态，不拿通用示例的结果替代 |
| **项目侧** | 被检项目自身的约束 | 冻结模块不许改；账号数据决定哪些区块渲染 | 提案 + 等裁决；用注入态做视觉证据，并标明它不是交互证据 |

## 2. 已知限制（逐条）

### 2.1 仪器层面

| 限制 | 实测依据 | 后果 | 风险 |
|---|---|---|---|
| 微信侧**没有 DOM 级读数** | 三种形态的 CDP 求值都返回 `appservice App.CDPEnable unimplemented`（`research-report.md` §5） | 样式只能读元素级声明（`el.style(p)`），伪元素、继承链中间值、CSSOM 规则拿不到 | 某些差异只能看到"位置/尺寸不对"，看不到"哪条规则导致的" |
| 微信截图**不是 1×** | 试点 `0.7846 × 0.7820`（306×660） | 区域按共享 CSS 子矩形各自归一化后再比；像素判定对文本改判墨迹签名 | 细线、1px 边框、亚像素抗锯齿在两个密度之间不可逐像素比 |
| 目标侧快照**只含已声明选择器** | 试点 12 节点 vs 原型 127 节点 | 几何覆盖 = 已映射节点，不是整页 | 未映射区域的问题只能从像素图上看出，不能定位到声明 |
| 行数在微信侧是**推断值** | 描述符 `capabilities.lineCount: false` | 排版维度对这个平台降级，`provenance: inferred` | 换行差异可能被判成"可能"，而不是确定 |
| 只有一个浏览器引擎 | 本机只有 Chromium（Playwright 1.63.0-alpha） | "两个渲染器的抗锯齿差异"造不出来，只能用合成层等效物（`experiments.md` §3.1） | 真实跨引擎栅格差异未被实验覆盖 |

### 2.2 判定层面

| 限制 | 实测依据 | 后果 |
|---|---|---|
| **20px 以上字重的像素级检出失败** | `b-weight`：14/13/12px 墨量 ×1.43/1.41/1.41 ⇒ FAIL；20px 标题 1.087 ⇒ PASS（`experiments.md` §3.6） | 大字重变化只能靠 `font-weight` 声明比较；若两侧都缺该声明，只能 UNVERIFIED |
| **接受项只到类别粒度** | `acceptedDifferences` 无按轴切分 | 混合配对（宽差合理 + 高差是缺陷）无法只接受一半；试点 `primary-sub` 因此保留 FAIL |
| **盒模型不同 ⇒ 标量宽高不判** | 试点 `primary dh +32` 来自 border-box/content-box | 这是"不误判"的代价：当盒模型不同时，宽高数值本身不再有可比性 |
| **阴影/图标/渐变没有专门判据** | 只有 `box-shadow` 归一化比较与整块像素 | 复杂阴影、图标内部路径变形、渐变方向错误只能报"像素不同"，归因不到声明 |
| **墨迹签名是代理量** | bbox 2px + 墨量比 0.3 | 它回答"看起来是不是同一团字"，不回答"字形对不对" |

### 2.3 流程层面（本轮没有执行的）

| 项 | 状态 | 原因 | 剩余风险 |
|---|---|---|---|
| OurTrail 实现层修复（P1–P5） | **BLOCKED** | 目标页在冻结模块 `pages/weather-hub/**`，任务书禁止为试点解除冻结 | 缺陷已定位到声明，但"修完复验"的闭环在这个项目上只有声明层证据（C-1） |
| 小程序侧实验 A/B | **NOT_RUN** | 注入已知偏差要改冻结页面 | 误报控制只有试点一次真实样本（0 dpr3/缩放），没有成组数据 |
| `components` / `sections` 声明 | 未开始 | 试点配置未声明 | `component-contracts` 与 `page-layout` 为空 ⇒ 契约覆盖 UNVERIFIED；组件级回归没有契约依据 |
| 第三平台适配器 | 未做 | 只有 Web 与微信两个实现 | 适配器契约与 `LIMITATIONS.md` 流程可用，但没有第三方实测 |
| 多视口 / 暗色 / RTL | 未覆盖 | 实验固定 390×844（`b-dpr2` 例外 2×） | 响应式规则只在配置里声明，未被实验验证 |
| 动效 / 过渡 / 滚动容器内状态 | 未覆盖 | 截图是静态帧，交互驱动只做 tap/input/wait/waitFor | 动画期间的版式问题、滚动后的固定定位问题都在覆盖面之外 |
| 结构级重排的自动归因 | 样本 1 | 只有试点 `tabs −89.99` 一次手工级联分解 | 复杂重排可能只给位移读数，指不到具体声明 |

## 3. 路线图（按"能解锁什么"排序，不按工作量）

### P0 — 打通目标项目上的闭环（解锁"修复闭环"这一条主张）

1. **取得授权后用 P1/P2 补丁跑一轮修复 + 复验**（`pilot-ourtrail.md` §9）。
   验收口径：修前 FAIL 的配对集合、修后同集合转 PASS，且原先 PASS 的配对不回退；
   真机截图必须是新 bundle（用新声明自证，如 `box-sizing` 生效后的宽度读数）。
2. **一个可注入的沙盒页做小程序侧成组 A/B**（不改冻结页）：新建 `pages/lab` 式的隔离页，
   注入 8 类已知偏差与 6 类允许差异，把 `experiments.md` 的 A/B 在小程序链路上重做一遍。
3. **结构级归因规则**：把试点里手工做的"级联分解"写成可复核的步骤
   （父级 dy 偏移 ⇒ 逐子级 residual；负数抵扣要两个方向分别报），并用 `c-repair` 的级联夹具当回归。

### P1 — 让判据更细（解锁"能发现哪些差异"）

4. **大字号字重的第二判据**：不能只靠墨量比。候选是"字重变化时字形笔画宽度分布"，
   但必须先证明它不把抗锯齿误判成字重（`probe-aa.js` 的合成层样本可用作反例集）。
5. **阴影 / 图标 / 渐变的专用读数**：至少把"位置与尺寸对、内部形状不同"与"整体错位"分开，
   否则修复阶段无法判断该改 box-shadow 还是改布局。
6. **多视口矩阵**：375 / 390 / 414 与暗色模式；配置已能声明 viewport，缺的是实验与夹具。

### P2 — 扩大适用面

7. **第三个适配器**（如纯 Web 的 React/Vue 项目）：验证 `adapters/` 契约真的与平台无关，
   而不是"只对两个已知平台成立"。
8. **报告到源码的映射**：pairId → 目标侧选择器 → 文件/行号。
   本轮靠人工 grep（试点 5 条根因都落到了行号），但它还没产品化。
9. **CI 集成**：`pf verify` 退出码已可作门禁，缺的是"只在受影响的页面上跑"的增量策略。

## 4. 十个问题的回答

### 1. 目前哪些 Skill 已经真正可运行？

七个技能都有 `SKILL.md`，且都指向真实子命令；但**技能本身不执行**，执行体是 `cli/pf.js`。
按"本轮真实调用过"统计：

| 技能 | 状态 | 证据 |
|---|---|---|
| `prototype-inspector` | 运行过 | 试点与示例的原型捕获（截图 + 快照 + 版本信息） |
| `target-platform-adapter` | 运行过 | 微信侧真实捕获（dpr 3 / 缩放 0.7846×0.7820） |
| `design-contract-builder` | 运行过 | 两侧 7 份契约；`tests/contracts.test.js` 126 断言守结构 |
| `visual-fidelity-analyzer` | 运行过 | 试点 15 对实态 + 实验 A/B；五维评分卡产物齐全 |
| `interaction-fidelity-validator` | 运行过 | 试点 4/4 PASS，每条带 `real-action-and-observation` |
| `fidelity-repair-agent` | 通用栈运行过；OurTrail **BLOCKED** | 实验 C-2 一轮收敛；试点只出提案（授权） |
| `fidelity-orchestrator` | 运行过 | `pf verify` 串联；`verify-steps.json` 记录逐步状态 |

技能文本的可执行性由 `tests/skills.test.js`（26 断言）守住——它检查的是**结构**（必填小节、
命令与 CLI 一致），不是"技能被读过"。两者别混为一谈。

### 2. 哪些只是原型或接口？

- **`components` / `sections` 声明**：契约文件有、schema 有、技能有，但试点配置没声明 ⇒ 产物为空、
  覆盖记 UNVERIFIED。
- **新平台适配器**：`adapters/README.md` 的接入流程与描述符 schema 是完成的，
  但没有第三个平台的实现与实验。
- **`acceptedDifferences` 的按轴粒度**：接口只有类别，按轴切分没做（这是判定层限制，不是待办遗漏）。
- **多 Agent 并行编排**：本轮确实用过并行子 Agent 做调研与实现，但"跨会话、可恢复的编排"
  没有产品化 —— `skills/README.md` 只规定角色与文件所有权，不提供运行时。

### 4. 系统能发现哪些类型的视觉差异？

按本轮的实测覆盖，能稳定发现并**归类**：

| 类型 | 实测证据 |
|---|---|
| 位置偏移 | `pos-8`：`dx −8`；试点 `tabs dy −89.99` |
| 间距变化 | `gap-4`；试点 `primary-sub dy +10.01`（margin 4/0） |
| 尺寸变化 | 试点 `primary dh +32`、`actions dh +34`、`foot dh +17` |
| 盒模型差异 | 试点 `box-sizing border-box/content-box` 被作为原因字段给出 |
| 字号 / 行高 | 实验 A 两项；试点 `eyebrow line-height normal/22px` |
| 字重（声明级 + 小字号像素级） | 试点 `title 730/700`；`b-weight` 12–14px 墨量 ×1.4 |
| 颜色 / 圆角 | 实验 A `color` 3.006%、`radius` 2.742% |
| 图片裁切 | 实验 A `crop` 86.429% |
| 文本换行 / 行数 | 实验 A `wrap`；试点 `foot` 行数 +1 |
| 文本内容差异 | 试点 `foot`（`text` 类别，按声明接受） |
| 墨量（"看起来是不是同一团字"） | 实验 B `b-weight`、`b-aa` |
| 交互后果 | 试点 4/4（`data.homeTab`、`.wh-tab.on` 文本、弹层开关） |

### 5. 对哪些差异仍然无能为力？

- **20px 以上的字重变化**（墨量比 1.087，漏报）——只能靠声明比较。
- **真实抗锯齿差异**——本机只有一个渲染器，用合成层等效物替代，不等于真机双引擎差异。
- **图标/矢量内部形变、复杂阴影、渐变方向**——只有像素读数，没有归因到声明的判据。
- **结构级重排的自动归因**——能报位移，不能自动说"是父级 flex 属性导致的"。
- **动效/过渡期间**的版式与固定定位——截图是静态帧。
- **滚动容器内部状态**——交互驱动只支持 tap/input/wait/waitFor，没有滚动动作。
- **微信侧的 DOM 级样式来源**——CDP 不可用，只有元素级读数。
- **跨设备字体族差异**——会表现为墨量与行数变化，但无法区分"字体不同"与"字重不同"。

### 6. 是否能够将差异定位到具体组件或样式？

**能到两级，第三级做不到。**

1. **区域级**：`pairId` + 每对三张图（prototype / target / diff），可回查。
2. **声明级**：`failingStyles` 直接给 `prop` 与两侧值。实验 C-2 靠它命名
   `font-size 12/14`、`border-radius 8/12`、`margin [16,0,0,0]/[10,0,0,0]`；
   试点 5 条根因全部落到 `file:line`（`app.wxss:82`、`weather-hub.wxss:14/166` 等）。
3. **源码行号级**：**没有产品化**——本轮是人工 grep 得到的。

限制：只有"已声明 styleProps"才会进声明级比较；没声明的属性只能通过几何/像素间接发现。

### 7. 是否真正完成了修复闭环？

**能力上完成了；在 OurTrail 上因授权没有执行。**

- 通用栈（`examples/generic-web`，与 OurTrail 无关）：3 处声明漂移 → 报告命名声明 →
  锚点命中恰为 1 的修复 → 复验 8/8 PASS、几何 0、像素 0、退出码 0、无回归、**1 轮收敛**。
- OurTrail：视觉 10 对 FAIL 已归因，交互 4/4 PASS；**实现层 0 行改动**（冻结模块），
  只修了 1 处**声明层**问题（`tab-points` 断言从空态节点改为真实交互后果，3/4 → 4/4，视觉读数逐字节不变）。

所以"修复闭环"这条主张的证据在通用示例上，不在目标项目上；这两件事不能互相顶替。

### 8. 是否能在另一个项目中复用？

**能，且有实测**：把 `examples/generic-web` 复制到仓库外的临时目录，
同一个 CLI 跑出 `specimen FAIL / b-identical PASS`，与仓库内**逐字段相同**
（20 个区域的 status/categories/dx/dy/dw/dh/像素/墨迹），且源码里 0 处 OurTrail 引用、
`codeVersion` 为 `null`（provenance 不是借来的）。

代价与边界：换项目要**重写配置**（页面、映射、状态、交互、接受项）——这是设计使然，不是缺陷；
换**平台**没有实验覆盖（见 §2.3）。

### 9. OurTrail 的真实试点效果如何？

- **页面判定 FAIL**：15 对实态里 1 PASS / 10 FAIL / 4 NOT_APPLICABLE；
  五维：几何 12/22 失败、排版 5/26、外观 8/24、状态 4/4 PASS、交互 4/4 PASS。
- **失败是可解释的**：12 处几何失败拆成 5 条根因——
  G1 全局 `border-box` 缺失（`92 = 60 + 15×2 + 1×2`）、G2 继承 `app.wxss:82 line-height: 22px`、
  G3 字重 650/730/680 → 600/700、G4 头部 padding 22 vs 14、G5 `primary-sub` 少 4px 上边距。
- **级联已经算平**：`tabs −89.99 = −124（已接受的数据差）+ 32（盒模型）+ 2（边框）`。
- **一个反直觉的读数**：`eyebrow` 的 `+8` 行高与 `header` 的 `−8` padding 恰好抵消，
  所以 `title`/`sub` 的 `dy` 读 0 —— 这不是"没问题"，是两笔错误互相抵消。
- **没做到的**：实现层修复（BLOCKED）、真机 bundle 新鲜度的自动证明、跨设备与 375/414 宽度。

### 10. 下一阶段应该优先增强哪些能力？

按"解锁什么"排：

1. **拿到授权，把 P1/P2 补丁真修一轮并复验**（解锁"在目标项目上的修复闭环"）。
2. **做一个小程序侧的可注入沙盒页，把 A/B 实验搬到小程序链路上**（解锁"误报控制在小程序上是成组的，而不是一次样本"）。
3. **结构级归因规则**（把试点里手工的级联分解变成可复核步骤）。
4. 大字号字重判据、阴影/图标判据（让"能发现哪些差异"再宽一档）。
5. 多视口矩阵、滚动动作、第三个适配器（扩大适用面）。

不排在前面的：把技能数量继续加、把报告做得更漂亮、给一个总分。
本轮所有证据都说明这三件事不会让结论更可信，只会让它更难复核。
