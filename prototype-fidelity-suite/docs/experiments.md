## 1. 方法与共同前提

- **示例栈与 OurTrail 无关**：`examples/generic-web/` 只有静态 HTML/CSS/JS、两张图片和一个 `card.js`；
  页面 `b/base.html` 是 390×844 的单屏卡片页（标题 / 卡片 / 图片 / 按钮 / 说明）。
- **同一个入口**：所有实验都调 `cli/pf.js verify`（capture → contract → diff → validate），
  实验脚本只做四件事——造夹具、断言读数、写结果、判退出码。脚本里没有第二套比对实现。
- **五态与退出码**：`PASS / FAIL / UNVERIFIED / BLOCKED / NOT_APPLICABLE`；
  `0 PASS`、`1 FAIL`、`2` 环境/配置错误或 `UNVERIFIED`（"什么都没测到"永不返回 0）。
  实验 D 里出现过一次 `2`，正是这条规则生效的副产品（§4.4）。
- **反空转（anti-vacuity）**：每个"应当通过"的用例必须同时证明**它要容忍的那个差异真的发生了**。
  例：`b-aa` 要求 `pixelDiffRatio > 2%` 才算 AA 差异存在；`b-dpr2` 要求截图 `scale === 2` 且
  降采样后像素差 `> 5%`；`b-dynamic-declared` 要求时钟真的变了（`> 5%`）。
  没有这些门，"通过"可能来自"根本没有任何差异"。
- **阴性对照**：B 里有两组必须报红的用例（未声明的动态文本、字重变化），
  用来证明"全部通过"不是闸门失灵。

## 2. 实验 A · 已知偏差检测

夹具：`specimen` 页，原型 = 目标之外的同一份 `b/base.html`，在目标侧注入 8 处偏差；
另有 4 个区域（`ctrl-1..4`）完全不改，作为对照。

| 注入 | 期望类别 | 实测类别 | 关键读数 |
|---|---|---|---|
| 8px 位置偏差 `pos-8` | position | position | `dx = -8`，像素差 **0** |
| 4px 间距偏差 `gap-4` | spacing | spacing | 像素差 1.839% |
| 字号变化 `font-size` | typography | typography + pixel | 像素差 25.893% |
| 行高变化 `line-height` | typography | typography + pixel | 像素差 12.712% |
| 圆角变化 `radius` | appearance | appearance + pixel | 像素差 2.742% |
| 颜色变化 `color` | appearance | appearance + pixel | 像素差 3.006% |
| 图片裁切 `crop` | pixel | pixel | 像素差 86.429% |
| 文本换行 `wrap` | text-wrap | text-wrap + pixel | 像素差 11.645% |

判定：整页 `FAIL`、进程退出码 1、失败集合**恰好**等于注入的 8 项、4 个对照全部 PASS 且 0 类别、
`warnings` 为空。

两条方法学结论（都是从读数里读出来的，不是设计意图）：

1. **几何与像素回答不同的问题**。`pos-8` 的 `dx = -8` 而像素差为 0.000%：
   纯位移把盒子挪走了、内容一个字节没变。所以"像素差为 0"不能证明"位置对"，
   反之"像素差很大"也不能告诉你是位置还是内容——两个通道必须分开读。
2. **归类比"有差异"更有信息量**。8 项全部落进注入的类别，没有一项被错归；
   字号/行高落到 `typography` 而不是笼统的 `pixel`，圆角/颜色落到 `appearance`。
   修复阶段（实验 C）能直接拿到"改哪条声明"，靠的就是这一层归类。

## 3. 实验 B · 误报控制

"允许的渲染差异"共 6 类，每类一页；另设 2 个必须报红的阴性对照。

| 用例 | 注入的允许差异 | 反空转门（实测） | 结果 |
|---|---|---|---|
| `b-aa` | 字形栅格化差异（合成层：`will-change:transform; transform:translateZ(0)`） | 正文像素差 **4.741% > 2%** | PASS，全部区域 PASS |
| `b-dpr2` | DPR 1 → 2 采集后降采样 | `screenshotScale = 2.0`；降采样像素差 **13.338% > 5%**；容器被声明子元素遮罩 `ratio > 0.5` | PASS |
| `b-taller` | 视口更高（下方多出空白） | 全区域 PASS（多余空白不进入任何配对） | PASS |
| `b-dynamic-declared` | 运行中变化的时钟文本（已声明） | 像素差 **10.102% > 5%**，且 `pixel.judged === false` | PASS，几何与存在性仍判 |
| `b-dynamic-undeclared` | 同一份字节，**不声明** | 像素差 **10.752%**（与上一行相差 < 2 个百分点） | **FAIL**，只有 `b-clock` 失败，类别 `text + ink` |
| `b-statusbar` | 外壳多出 24px 状态栏 | `alignment.shift = {x:0, y:24}` 被实际应用 | PASS |
| `b-weight`（阴性） | 字重变化 | 见 §3.6 | **FAIL**（按预期） |

### 3.1 抗锯齿（`b-aa`）——先找"差异制造器"，再谈容忍

要让"容忍抗锯齿"这句话有意义，必须先能**造出**抗锯齿差异。`probe-aa.js` 试了四种处理，
读数落在 `aa-probe.json`：

| 处理 | 几何 | 像素差（各区域最大） | 墨量比（最大偏差） | 能否当 AA 等效物 |
|---|---|---|---|---|
| 启动参数（`--disable-font-subpixel-positioning`、`--font-render-hinting=none`） | 全 0 | **0** | 0 | 否（什么都没改） |
| `text-rendering: geometricPrecision` | 全 0 | **0** | 0 | 否（什么都没改） |
| `-webkit-font-smoothing: antialiased` | 全 0 | **0** | 0 | 否（什么都没改） |
| `-webkit-text-stroke: 0.3px currentColor` | 全 0 | 11.28% | 17.2% | 否（动了墨量 ⇒ 那是描边，不是栅格差异） |
| 合成层（`will-change` + `translateZ(0)`） | 全 0 | 0.498%–4.741% | 0.984–1.129（最大偏差 12.9%，留在 0.3 容差内） | **是**（唯一满足"动了像素、没动墨量"的处理） |

所以 `b-aa` 的"AA 差异"来自合成层：像素真的变了（4.741%）、墨迹签名没变（PASS）⇒ 报 PASS。
**更正一句旧话**：我此前说过"本机无法造出抗锯齿差异"——那对前三种处理成立，对合成层不成立，
已按 `aa-probe.json` 收回。同时要如实说明它的边界：合成层不是"两个真实渲染器的字体抗锯齿差异"，
而是"同尺寸、同墨量的栅格差异"，属于**等效物**，不等同于真机证据（§6）。

### 3.2 DPR（`b-dpr2`）

2× 采集后降采样必然改变像素；几何不受影响。`b-desc` 像素差 13.338%，墨迹比 1.108（在 0.3 容差内）⇒ PASS。
容器 `b-card` 的像素判定用了"声明子元素遮罩"（`masked.ratio > 0.5`），
避免把子元素的差异在父容器上再记一次账。

### 3.3 视口尺寸（`b-taller`）

页面更高、下方多出空白：所有已声明区域都在原位，全部 PASS。
这条用例的作用是证明"截图尺寸不同"本身不构成失败——**区域按共享 CSS 子矩形裁切**，
多出来的地方不属于任何配对。

### 3.4 动态内容：一对只差声明（`b-dynamic-declared` / `b-dynamic-undeclared`）

两页的 HTML 完全相同，只有 `pf.config.json` 里的声明不同：

- 声明后：`b-clock` 的像素与墨迹通道被**观察**（`judged: false`）但不参与判定，
  存在性与几何照判 ⇒ PASS。
- 不声明：同一份截图报 FAIL，类别 `text + ink`，且**只有** `b-clock` 失败。

两次读数 10.102% vs 10.752%（相差 < 2 个百分点）证明：**改变判定的是声明，不是渲染**。
注意这两个数是**会漂的**——时钟显示的是真实当前时间，每次运行的内容都不同；
所以断言写的是"两者相差 < 2 个百分点"而不是具体数值，文档里抄下来的数也只是一个时点的读数。
这也是"声明不能用来洗白真差异"的边界——声明只关掉内容通道，几何与存在性没有任何豁免。

### 3.5 状态栏（`b-statusbar`）

外壳多 24px：配置声明 `alignment.anchor = "b-title"`，重定基只作用 `dy`，实测 `shift.y = 24` 已应用 ⇒ PASS。
尺寸永不重定基（否则"外壳更高"会被洗成"版式正确"）。同批三条断言：`isAnchor === true` 且锚点自身
`dx = dy = 0`（它**是原点**，不是被判的对象）；重定基之后原始位移仍以 `rawDy = 24` 保留可见——
否则"对齐过了"就再也看不出外壳差了多少。

### 3.6 阴性对照与一处**已登记的漏报**（`b-weight`）

字重变化必须报红，否则整套"误报控制"就是闸门全开。实测：

| 区域 | 字号 | 墨迹读数 | 结果 |
|---|---|---|---|
| `b-label` | 14px | 墨量 ×1.43 | FAIL（正确） |
| `b-desc` | 13px | 墨量 ×1.41 | FAIL（正确） |
| `b-note` | 12px | 墨量 ×1.41 | FAIL（正确） |
| `b-title` | 20px | 墨量比 1.087 | **PASS（漏报）** |

即：墨迹签名对小字号字重敏感、对 20px 标题不敏感。这条**不修**（改了会牵动整条墨迹阈值），
如实记进 §6 与 `docs/limitations-roadmap.md`；20px 以上的字重差异目前只能靠
`font-weight` 这条**声明**比较（试点里 `title` 的 `730 → 700` 就是这么抓到的）。

## 4. 实验 C · 修复有效性

两个案例：试点内的一次**声明层**修复（C-1），与通用栈上的一次**实现层**修复（C-2）。
两条都按任务书要求的六项记录。

### 4.1 C-1 · 声明层（OurTrail 试点内，`tab-points`）

| 项 | 内容 |
|---|---|
| 修复前差异 | `tab-points` FAIL：`textIncludes(.wh-quiet, '常用地点')` 找不到节点 |
| 根因 | 断言把**依赖数据状态**的空态节点当成不变量；该账号已有 2 条常用地点 |
| 修改内容 | `pf.config.json`：改判 `.wh-tab.on` 的文本 + `data.homeTab === 'points'`（页面 0 改动） |
| 修复后差异 | 交互 3/4 → 4/4；视觉区域读数**逐字节不变**（同一批报告，仍是 10 项失败） |
| 是否引入新问题 | 无 |
| 迭代次数 | 1 |

### 4.2 C-2 · 实现层（`examples/generic-web`，与 OurTrail 无关）

夹具 `c-repair/before.html` = 基准页 + 一个 `<style>` 块，内含三处"手写实现时很常见"的漂移
（文件里写明它们不是黄金值）。运行器把它复制成 `c-repair/target.html`（复制前后断言 sha256 一致）。

| 项 | 内容 |
|---|---|
| 修复前差异 | 8 对里 **7 对 FAIL**：`b-label` 字号 12→14、行高 16→18；`b-card` 圆角 8→12；`b-btn` `margin-top` 16→10 |
| 级联（逐项断言） | `b-clock`/`b-desc`/`b-img` `dy +2`；`b-btn`/`b-note` `dy −4`；`b-card` `dh +2`；`b-note` **没有自身失败声明** ⇒ 纯级联 |
| 根因定位 | 报告逐条给出**声明**：`font-size 12/14`、`border-radius 8/12`、`margin [16,0,0,0]/[10,0,0,0]` |
| 修改内容 | 把三处声明改回原型值；每处要求**锚点命中数恰为 1**（否则该条修复不成立，不静默改错行） |
| 修复后差异 | 8/8 PASS；几何 0、像素 0、ink PASS；退出码 **0** |
| 是否引入新问题 | 无（原本 PASS 的 `b-title` 仍 PASS） |
| 迭代次数 | **1**（首轮收敛） |

写盘前后都断言 sha256 变化，防止"报告说修好了、文件其实没变"。

### 4.3 C 的三次首版失败（保留记录）

第一次跑 C 时三条断言报红。它们都不是工具缺陷，但都不是"改门放过"解决的：

1. **预期失败集合写错**：只列了 3 个注入项，忽略了级联（实际 7 项失败）。
   改的是**期望**（补 `cascades` 数组并逐区域断言 dy），不是放宽判据。
2. **一个断言表达两个方向的位移**：用"合计 6px"断言 `b-btn`，实测 −4（父级 +2 与自身 −6 相抵）。
   改成逐区域 dy（2/2/2/−4/−4），因为"合计"会把两个相反的事实压成一个看不出错的和。
3. **修复后退出码 2 而不是 0**：该页 `interactions: []` ⇒ 交互维度 `0/0` = UNVERIFIED ⇒ 整页 UNVERIFIED。
   **这是规则生效**（缺证据不得变为 PASS），不是要绕过的障碍；修法是给该页补一条**真实交互**
   （`toggle-note`：`tap #b-btn` → `wait 150` → `#b-note` 文本含「已展开」）。
   补完后 after 侧 `0`，且这条交互自己也进了断言。

第 3 条是本轮最值得记的一条：**"没有交互声明"不是"交互没问题"**。

## 5. 实验 D · 可迁移性

- 把 `examples/generic-web` 的源文件复制到 `os.tmpdir()` 下新建的临时目录（**仓库外**），
  用同一个 CLI 对新目录执行 `verify`（`cwd` 仍在套件根，证明运行时不依赖被检项目的绝对位置）。
- 断言：

| 检查 | 实测 |
|---|---|
| 示例源里引用 OurTrail / 小程序的字样 | **0 处** |
| 副本在仓库外 | 是（`!dest.startsWith(SUITE)`） |
| provenance 不是借来的 | 副本报告的 `target.codeVersion === null` |
| `specimen`（有偏差）| 退出码 1、`FAIL`，与仓库内一致 |
| `b-identical`（无偏差）| 退出码 0、`PASS`，与仓库内一致 |
| 逐区域读数 | `specimen` 12 区、`b-identical` 8 区，`status / categories / dx / dy / dw / dh / pixelDiffRatio / ink` 全部相同（像素容差 1e-9） |

结论：核心与 Web 适配器不含任何 OurTrail 路径、组件或业务数据；换一个原型项目只需换
`pf.config.json` 与目标侧文件。**未证明的部分**：换一个**平台**（新适配器）没有实验覆盖，
那属于适配器契约与 `LIMITATIONS.md` 的职责，不在实验 D 的定义里。

## 6. 未完成与剩余风险（如实登记）

| 项 | 状态 | 原因 | 剩余风险 |
|---|---|---|---|
| 小程序侧的实验 A/B（成组注入偏差 / 成组允许差异） | **未做** | 注入偏差要改 `pages/weather-hub/**`（冻结模块，授权禁） | 小程序链路只有试点里的一次真实样本（0.7846×0.7820 缩放、dpr 3），误报控制没有成组证据 |
| 真实抗锯齿差异 | **替代品** | 本机只有一个渲染器（Chromium），造不出"两个渲染器"的自然差异 | §3.1 的合成层只是等效物；真机 AA 行为未知 |
| 20px 以上字重变化的像素级检出 | **已知漏报** | 墨迹签名对大字号不敏感（1.087 < 1.3 容差） | 只能靠 `font-weight` 声明比较兜底；若两侧声明都缺，该项 UNVERIFIED 而非 PASS |
| 多视口 / 暗色模式 / RTL | **未覆盖** | 实验固定 390×844 / dpr 1（`b-dpr2` 例外为 2×） | 响应式规则只在配置里声明，没有被实验验证 |
| OurTrail 实现层修复闭环 | **BLOCKED** | 改冻结模块需明确授权（任务书 §11） | 视觉缺陷已定位到声明（`pilot-ourtrail.md` §9），但没有"修完复验"的真机证据 |
| 结构级重排的自动归因 | **样本 1** | 只有试点 `tabs −89.99` 一次级联分解 | 复杂结构变化可能只给出位移读数而指不到具体声明 |

**不伪造成功率**：本报告不加权、不折算百分比。A 是 8/8 + 4/4，B 是 6/6 + 2/2 阴性对照，
C 是 1 轮收敛的两次记录，D 是逐字段相同 —— 都是可复核的计数。
"覆盖率 95%" 这类数字需要独立的样本定义与抽样方法，本轮没有做，因此不写。
