# 活动板块整体交互与按钮统一 · 2026-10-28

## 范围与边界

本轮是原生小程序的 M2 改进，不是 HTML 原型。用户将范围从发起活动扩大为整个活动板块，特别指出按钮观感问题。

覆盖首页、发现、活动详情、发起/编辑、报名、工作台，以及任务、活动通知、车辆联络、现场协作；名单、分车、现场面板同步处理。天气、个人中心、公共路线库和全站通知不跟随活动专用样式变化。

保留上轮尚未提交的四步编辑器工作。没有修改云函数、域模型、权限、报名授权、CAS、活动阶段与路线锁定规则，没有新增 npm 依赖。没有提交、推送、部署或发布真实活动。

## 依据与设计判断

使用用户指定的 `ui-ux-pro-max`，同时遵守项目 `ourtrail-ui` 的 token、主动作预算、触控尺寸和原生验收要求。技能检索的通用 outdoor/fitness 建议偏营销页，未采纳其橙色/蓝色配色和外部字体；采用现有森林绿、冷白纸面、系统字体。上轮发起流程的竞品研究继续参见 `activity-editor-iteration-2026-10-28.md`，本轮没有虚构新的市场调研结论。

改前确认的问题：

- 首页和详情的照片占据较多首屏，时间、集合信息和列表被推低；照片氛围和失败兜底值得保留。
- 多处小字入口与正文接近，主按钮、次按钮、工具导航的形态不够明确。
- 编辑器的保存按钮只有 12px 文字，和主要推进动作比例失衡；输入区域的边界主要靠底线。
- 紧凑活动卡标题与状态争夺一行宽度，路线事实单行裁切，窄屏不利于比较。
- 工作台切入面板后，顶部总量与面板统计同时占用较多空间；不能因此删除跨面板入口和真实人数。

## 按钮与控件契约

只在 `.activity-ui` 作用域生效，规则集中在 `miniprogram/app.wxss`，页面不复制配色：

- 主按钮：森林绿实底、16px 文案、单行 48px 高；14px 圆角复用 `--radius-card`，不新增 token。
- 次按钮：白底和可辨识描边；保存、分享、资料等不再像一段小字。
- 轻量动作：仍为透明文字按钮，至少 44px；删除/取消不升级为首屏实心主按钮。
- 导航：工作台工具使用图标、标题、说明和箭头，不继承提交按钮类。
- 页签：44px 触区、14px 字体、按压反馈；不能只改 class 而没有实际渲染读数。
- 表单：现有 16px 输入文字，明确描边与圆角；错误色与焦点仍可辨识。
- 禁用：作用域样式不得盖过禁用表达，原生 disabled 与类形式一致；业务 handler 的守卫未放松。

`style-semantics-test.js` 的旧解析器不认识后代选择器，本轮升级了祖先链匹配并增加隔离、类/属性禁用一致性、对比度、影子 token 与变异对照。没有简单删除旧围栏或将失败改为跳过。

## 验收方法与边界

原生驱动：`tools/verify-activity-suite-native.cjs`，编辑流程沿用 `tools/verify-editor-native.cjs`。外部 `miniprogram-automator` 只安装在 `/tmp`，不进入项目依赖。

夹具通过真实 domain reducer/selectors 在 Node 内存生成；小程序里拦截云调用并隔离 wx storage。所有真实云调用被替代，未允许的命令直接拒绝；结束恢复原有方法。这里的发布、授权、任务/通知样例仅存在测试进程内存，不是线上数据。

每次验收须注明 DevTools/SDK、模拟设备和视口。页面数据读取完成、真实点击产生的后果、渲染尺寸与人工截图审查分别登记；不把数据读取或截图数量当作业务通过数。物理手机、真实云写入与完整线上端到端不属于本轮已验范围。

证据与最终结果见 `evidence/activity-suite-2026-10-28/README.md`。改前截图来自同一原生项目；后续补充的任务/通知样例与现场协作账号用于扩展覆盖，不与改前空态冒充严格同数据对照。

## 中途发现与处理

- 车辆司机不是车辆联络授权。初版夹具缺联络 membership，车辆页真实拒绝，补齐测试权限后继续；未修改生产权限。
- 组件属性不能按普通节点 attribute 假设读取，改用组件 data 选择正确活动，不依赖列表首项。
- `getWeatherByPoint` 是只读天气请求。初版驱动将其归为未知操作并拦截，后续明确返回 unavailable，没有放行任何真实天气或写调用。
- 现场协作也需要独立 membership；补充独立测试协作者，不让组织者自动获得协作权限。
- 原生读数发现主/次按钮一度为 50/48px，同排不齐；修正主按钮行高后按最终像素复验。
- 通用 lifecycle 夹具的电话为 10 位，早期报名错误截图同时出现电话与授权缺项；最终专用夹具改为合法格式的样例号码，断言严格要求只有未授权这一项错误，避免其他校验掩盖授权测试。
- 旧测试将 `class="page {{...}}"`、80px 缩略图、工具的 button 类写死；按新布局更新这些结构契约，原业务、权限、四态和同步判据保留。
- 项目首次 CLI 重开停在项目列表，自动化端口未就绪；通过开发者工具界面重开 OurTrail 后启用自动化。失败运行保留为诊断，不计最终通过。
- 414px 首次导航断言在跳转完成前读取了旧页；原生界面随后已进入发现页，固定延时不能作为完成条件。驱动改为等待目标路由及加载状态，不改生产导航，也不以直接跳页替代点击验证。后续自动化连接超时与项目未实际打开分别留日志，重开目标项目后复验。

## 用户截图后的空首页补改

用户反馈本地编译仍像旧页面。对照截图、生产模板与上一批 `390/15-home-empty.png`，原因不是已证实的编译缓存：截图已含新增的发现图标和描边按钮，但无下一次同行时仍使用旧邀请卡结构。上一轮虽验证空态能渲染，却没有把它作为主要设计验收对象；有活动的样例截图不能代表该用户的实际空首页。

补改只涉及首页接线和 `next-up-card` 展示组件：无任何活动时增加有明确用途标签的现有山林氛围图、成组的发起/发现入口、活动保存后去向说明；图片失败保留森林底、文案和操作。只有历史活动/草稿但无下一场时采用紧凑无图版本，不挤占列表。有下一场时保留原有真实活动卡。没有添加示例活动或改变查询/权限。

原生驱动补入空首页专属判据：检查新标题与真实空状态、两按钮实际 48px 且同排、图片失败分支、实际点击发现和发起的目标路由。新增接线/事件回归，避免只凭新 class 或其他状态截图宣布完成。后续证据独立保存在 `evidence/home-empty-followup-2026-10-28/README.md`，上一批原始证据未覆盖。
