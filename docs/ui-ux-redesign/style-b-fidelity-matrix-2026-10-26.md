## 1. 为什么上一轮「实现程度不高」——三条可核事实

不是执行 Agent 偷懒，而是上一轮任务书把「逐屏重构」定义成了「收口」。

1. **任务书明文禁止重做。** `agent-handoff-style-b-2026-10-26.md:24`：「21 页均已按 D1–D11 落地；剩余工作是**收口、补验、按需修剩余差分**。任何「重做 21 页」的方案都视为越界。」同文件 `:50` 还禁止改 `brand-header` 结构，而参考板首页的身份恰恰由大图品牌头承担。
2. **「不改」建立在不可达内容态上。** `style-b-implementation-design-batch2b-2026-10-26.md:23` 把 9 页判为不改；其中 `signup`/`staff`/`vehicle` 的理由是「真实内容态不可达，凭 denied 截图改结构没有依据」（`:72-74`）。这是**验证缺口**，不是「版面已经对了」。
3. **验收只看门禁与 DOM 读数。** `evidence/style-b-2b-2026-10-26/README.md:65` 自己写着 `entry-layout 41/0（结构 E1；UI=NOT_RUN）`。静态门全绿、`page.data` 正常，页面仍然可以是旧样子——这正是铁律 21/32⑥ 反复说的「data 不是像素」。

**结论：** 要提保真度，必须换任务书：以「每屏有哪些结构块」为验收，而不是「门禁是否绿」；并且允许改 L2 组件与 `app.wxss` 的共用层。

## 3. 逐屏差距

### 01-1 首页 → `pages/home` · B

- **板上：** 大图品牌头（山景 + `OurTrail`）、头图内搜索、四类 chip（徒步/露营/登山/日程）、「推荐活动」大卡（封面 + 标题 + 日期 + 距离/爬升 + 剩余名额）、4 tab。
- **现状：** 品牌行 `home.wxml:2`；纯文字「下一次同行」卡 `:12`；两动作行 `:21`；搜索 `:37`；4 档功能筛选 `:42`；活动卡列表 `:61`。
- **差距：** 首屏没有图；状态卡没有封面；没有分类 chip 行（D10 已定不做）；搜索在第二屏（D4 有意）。
- **首屏目标：** 保留 D4 的「下一次同行」优先，但把状态卡做成板上的大图卡形态（封面 + scrim + 底部标题/日期/名额），动作行压到卡下；搜索与筛选保持第二屏。
- **备注：** 板上首屏是「发现优先」，与 D4 相反——这是**有意偏离**，只借卡片的构图与字阶，不借信息顺序。

### 01-2 全部活动 → `pages/discover` 列表 · B

- **板上：** 三个下拉触发（目的地/难度/日期）、缩略图行（左图右文）、标题/日期/距离/爬升/难度、底行金额与剩余名额、发丝线分隔。
- **现状：** 页头口号 `discover.wxml:10-12`；搜索 `:18`；列表/地图分段 `:28`；结果计数 `:32`；筛选与排序 chip `:35-37`；活动卡列表 `:58-79`。
- **差距：** 卡片不是「缩略图行」；筛选是 chip + sheet，不是三个下拉；金额不做；剩余名额未印。
- **首屏目标：** 列表改为板上的紧凑行（缩略图 96px + 两行文本 + 底部关系/名额），首屏能看到 4–5 场；顶部保留搜索 + 视图分段，筛选入口收成一个「筛选 · N」下拉触发。

- **板上：** 全屏地图、顶部悬浮搜索、地图标记、底部选中卡（缩略图/标题/日期/指标/金额/名额）+ 实心「查看详情」。
- **现状：** 地图卡嵌在页内 `discover.wxml:82-95`；callout 说明 `:96-101`；选中项复用 `activity-card compact` `:104-120`，卡整体可点，无底部固定 CTA。
- **差距：** 不是全屏地图；没有底部抽屉；没有独立「查看详情」按钮。
- **首屏目标：** 地图模式改为满屏地图 + 底部浮层卡 + 一个实心 CTA；列表模式不受影响。
- **边界：** 底图瓦片在 IDE 常为空白（Wave 1 起一直 UNVERIFIED），验收只认浮层与标记，不认底图。

### 01-4 筛选 → `pages/discover` 筛选 sheet · B

- **现状：** 活动行程节点有「天气」按钮（`activity.wxml:169-176`）跳天气页；`utils/route-schedule.js` 能按出发时刻推节点抵达日；没有路段级时间轴屏。
- **差距：** 缺的是把「路线节点 + 到达时刻」带进天气查询的展示层。
- **首屏目标：** **本轮不做**（属功能增量，不是版式）。登记为下一轮候选；现有节点天气入口保留。

### 04-4 详细数据 → `pages/weather` 数字表 · B

- **板上：** 温度/降水量/风速/云量四行；配图；数据来源 + 更新时间。
- **现状：** 可折叠数字表 `weather.wxml:464-490`；来源 `:492-495`。
- **差距：** 默认折叠；四行摘要没有；配图不做。
- **首屏目标：** 把四个高频量做成默认可见的四行摘要（值域而不是单点），完整表仍可展开；来源与更新时间常驻。

### 04-5 风险提示 → `pages/activity` 风险章 + 天气页 callout · B

- **板上：** 预警卡（高山路段可能有大风 + 建议）；「决策建议」1/2/3；「查看完整预报」。
- **现状：** 活动风险章 `activity.wxml:287-299`（风险标题 + 建议）；天气页 `weatherBrief.riskText` callout `:213-216`。
- **差距：** 没有独立的「决策建议」列表；没有「查看完整预报」的跨页入口。
- **首屏目标：** 风险章内加一条由既有风险数据派生的「决策建议」列表（按风险顺序，不新造结论），并给天气页回跳；**不新建页面**。

## 4. 冲突与推荐裁决

以下每条都需要一次性裁决。推荐列已经给出默认值；没有特别说明就按推荐执行。

### C1 沉浸式深绿页头 vs D2「仅 4 个 tab 页自定义导航」

- **板上：** `03-1`、`04-1` 在状态栏下就是深绿照片头，返回/分享是白色浮标。
- **约束：** `app.json` 下钻页走原生导航；批次二 F1 刚把 14 页统一为浅色导航、7 页继承深绿（`style-b-implementation-design-batch2b-2026-10-26.md:46`）。
- **推荐：不照做。** 保留原生返回栏，深绿色块从导航下方开始，用负边距贴住导航底；不做逐页 `navigationStyle: custom`。
- **后果：** 顶部少约 44px 沉浸感；换来胶囊避让、返回手势、21 页导航一致。

### C2 底部中央 `+` vs D5「4 等分 tab，无 FAB」

- **推荐：不照做。** 保留 4 等分 tab。首页已有「发起活动」primary，中央 FAB 会抢同一份预算。
- **后果：** 底栏与板不同；这是 D5 的既定偏离。

### C3 金额 / 收藏 / 剩余名额 vs 零金额纯工具

- **板上：** `¥680`、`¥580`、`约¥200`、收藏星、`剩余 6/12`。
- **约束：** 活动详情明写「OurTrail 不收款」（`activity.wxml:322`）；域内无价格/收藏字段；但 `remaining` 已由投影给出（`domain/selectors.js:651`）。
- **推荐：** 不做金额与收藏；「剩余名额」用既有 `remaining` 显示，不新增字段。板上底行改为「已确认 X/Y · 待审 Z」。
- **后果：** 列表/卡的右下信息与板不同；不破坏零金额定位。

### C4 详情页 4 tab vs D6 吸顶锚点

- **板上：** 概览/行程/装备/费用四段，切换内容。
- **约束：** 当前 6 段锚点（`activity.js:413-428`），正文不折叠；代码注释已说明为何不并成 5 段。
- **推荐：保留 6 段锚点**，只借板的分段条外观；不改成真 tab 切换。
- **后果：** 375 下每段约 55.8px，比板密；长文内容不会被藏起来。

### C5 工作台四段：待办/成员/交通/任务 vs 总览/名单/分车/现场

- **板上：** 第 4 段是「任务」，且「出发前检查」是清单。
- **现状：** `workspace.js:8` 是总览/名单/分车/现场；任务有独立页 `pages/tasks` 与工具入口 `workspace.wxml:92-109`。
- **推荐：保留现有四段名与内容**；总览顶部照板做「出发前检查」清单；任务继续留在工具区与独立页。
- **后果：** 第 4 段仍是现场；任务不作为工作台一级分区，避免隐藏组织者收尾主路径。

### C6 任务筛选 全部/个人/团队 vs 全部/待办/进行中/已完成

- **板上：** 按归属筛选。
- **约束：** V1 任务只存 `assigneeName` 文本、无账号绑定（`tasks.js:4`）；按名字判「个人」会误判。
- **推荐：不照做**，保留状态筛选。
- **后果：** 筛选项与板不同；不改 schema、不引入跨账号指派。

### C7 04-1「天气升级」的归属

- **板上：** 活动级页头 + 出发窗口卡。
- **现状：** 活动级摘要已在 `activity.wxml:196-228`；`weather-hub` 是点位查询工具。
- **推荐：把 04-1 的保真目标指到 `pages/activity` 的天气章**；`weather-hub` 只做视觉语言对齐，不改成活动页，也不新建第二个活动天气入口。
- **后果：** `weather-hub` 不与 04-1 逐屏对照；避免两个入口说同一件事。

### C8 03-5 现场通知：人员动态流 vs 结构化通知

- **板上：** 头像/时间/正文/图片/查看天气，像群聊。
- **约束：** 域内通知无作者头像、图片消息、回复（`anotices.wxml:8-25`、`notices.wxml:10-46`）。
- **推荐：不改成聊天流。** 用现有通知模型做板上排版（发布者/时间/正文/关联活动/查看天气）；图片与回复不做。
- **后果：** 观感更接近公告栏；不新增 schema/云函数。

### C9 页面口号 / 眉题

- **板上：** 没有「看看别人在约什么」这类口号，身份由标题承担。
- **现状：** `discover.wxml:10-12`、`weather-hub.wxml:7-11`、`anotices.wxml:10`、`weather.wxml:9`、`workspace.js:20` 仍有口号式副标题。
- **推荐：有参考屏的 8 页删除口号**，只保留解释数据口径或诚实性的说明（天气概率、不收款、缓存时效）。无参考屏的 13 页本轮不动。
- **后果：** 首屏少一行、更接近板；「通知」身份仍由分区小字承担（D8 代价条款）。

### C10 装饰性照片

- **板上：** 首页大图、详情照片、通知配图、天气配图。
- **现状：** `activity-card.wxml` 注释明写封面是 `utils/covers.js` 按 id 选的气氛图、非实拍；`activity-hero` 有真实封面与兜底两分支；没有通知图片模型。
- **推荐：不新增素材。** 继续「真实封面优先、现有氛围图兜底」；只放真实内容图（活动介绍图、GPX 剖面）。通知配图与天气配图不做。
- **后果：** 板上纯装饰图位不出现；不制造「现场感」的假证据。

### C11（范围，不必裁决）04-3 路线天气与 04-5 风险提示

- `04-3` 需要把路线节点 + 推算时刻带进天气页，属功能增量；本轮只登记，不实现。
- `04-5` 不新建页面，落在活动风险章与天气页回跳；决策建议只能由既有风险数据派生。

## 5. 无参考屏的 13 页怎么处理

只做三件事：① 跟随 slice 0 的全局语言（token、卡片、分区头、按钮）自动收敛；② 保证导航、四态、底部留白不因共用层改动而回归；③ 有真实内容态的页面（`me`、`editor`、`routes`、`route`、`route-edit`、`weather-chart`）做一次首屏结构审查，但不发明板上没有的模块。

`signup`/`staff`/`vehicle` 的真实内容态在当前账号下不可达（批次二已登记 UNVERIFIED）。本轮**不凭 denied 态改结构**；要验这三页，必须先造出可达数据或换账号。这是验证前置，不是设计问题。

## 6. 结论

上一轮交付的是「收口」：共用层没动、9 页判不改、验收只看门禁。要把板落地，必须按屏拆结构、先冻结共用层、每屏以「板上的结构块是否出现」验收，而不是以「门禁通过」验收。
