# 发现活动封面比例修正 · 2026-10-28

## 范围与根因

用户截图中的发现列表使用 `activity-card` 的 `compact + flat` 形态。上一轮将共享缩略图收为固定 64×76px，但右侧标题、状态、路线与人数会继续增高，造成左侧封面过小且下方留空。发现行同时继承卡片左右各 12px 的内边距，与页面边距重复。

仅修改 `components/activity-card/activity-card.wxss` 的 flat 变体：封面宽 104px、最小高 128px，与右侧内容等高；图片保留 `aspectFill` 等比例裁切，不拉伸。去掉 flat 行横向内边距，上下保留 16px。首页非 flat 紧凑卡仍为 64×76px，featured 卡、查询与筛选、地图、跳转、权限和云函数未修改。

## 验证环境与数据

- 微信开发者工具 2.02.2609231 RC，基础库 3.8.12，WebView；375/390 为 iPhone 预设，414 为 Mac 宽屏预设，不是物理手机。
- 修改后关闭并重新打开 OurTrail 项目，再连接原生自动化。封面回读 104px、图片/文字区等高且左侧内边距为零，证明新样式实际生效。
- `*-real-list.png` 来自真实云端发现列表，50 条结果、`loading=false`、`denied=''`。没有用模拟接口代替活动读取，也没有发起云端写命令。
- `*-long-title.png` 是当前首张组件上的临时排版数据：100 字混合长标题、长路线名称和四项指标。`*-failed-cover.png` 直接设置组件失败态，仅验证隐藏封面后的排版，不代表真实弱网测试。
- 每档验证后恢复组件完整原始数据，再回读真实标题与尺寸；普通紧凑形态也通过 64×76px 控制检查。未改用户草稿或持久化数据。
- 已恢复原来的 390px 机型。自动化连接均已断开。
