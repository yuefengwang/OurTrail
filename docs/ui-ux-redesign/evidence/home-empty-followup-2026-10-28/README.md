# 空首页补改 · 用户截图反馈

## 原因

`before/user.png` 是用户本地编译后的截图；`before/native-390.png` 是上一轮对应空状态的原生截图。两者都显示同一旧布局，且已有新图标/描边按钮，因此不能把问题推给编译缓存。此前对有活动状态的调整较多，无活动状态仅套用了按钮样式，整体结构没有迭代到位。

## 修正

- 无活动：现有山林摄影 + 明确的“场景氛围图”标签 + 出发引导；不冒充推荐活动或实拍。
- 发起/发现：合并在同一操作组，一主一次、同排 48px，不再上下堆两个满宽按钮。复用原页面路由，不改变发起和发现逻辑。
- 说明参与/发起后的活动会显示在这里；无数据时仍不显示没有意义的搜索和筛选。
- 只有草稿/历史活动而没有下一场：紧凑无图版本，保留原活动列表；有下一场不改其事实和进入详情的行为。
- 图片失败：退回森林底，仍有说明、标题和两个入口。

## 验证方式

使用同一真实小程序、DevTools 2.02.2609231 RC / SDK 3.8.12，重新编译后运行生产页面。以无活动账号的内存授权投影进入空首页，既不注入虚假活动来撑页面，也不进行真实云写入。API/storage mock 结束恢复；最终重开普通项目，清除测试运行时。

375×812 和 390×844 是 iPhone 模拟器预设；414×896 是 Mac 宽屏预设，不是物理手机。每个目录内有完整原生截图与原始 `readings.json`，重点查看 `15-home-empty.png` 和 `15b-home-empty-image-fallback.png`。

三档各 **85/85 条混合检查通过、21 张截图、0 未捕获异常、0 未允许云操作**。三档空首页人工看图无按钮挤压、左右溢出或底栏遮挡；按钮实际均为 48px。

新增原生检查包括：真实空状态与新标题、两按钮高度/同排/边界、失败兜底、真实 tap 后进入发现和编辑页。原有有活动状态、详情、工作台和报名的检查继续执行。图片失败用组件错误处理方法受控注入，仅证明该降级分支，不冒称实际断网测试。

26 套相关回归合计 **1814 条通过、0 失败**（入口套件 41→47，其余计数不变）。静态门 `check.js`、`check-handlers.js`、`git diff --check` 通过，唯一旧死 handler `editor.onNumber` 未增加。原始输出见 `logs/`。

物理手机、软键盘、系统大字体和真实云写入仍未验证；本次没有重新验证未修改的完整四步编辑器流程。原生检查总数包含数据、布局、降级注入与点击后果，不等同于纯交互用例数。未提交、推送、上传或部署。
