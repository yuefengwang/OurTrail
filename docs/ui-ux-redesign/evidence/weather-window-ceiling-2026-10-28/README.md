# 云层剖面天花板 9,750 m：一次授权重编译后的真机（模拟器）回读

**日期**：2026-10-28 · **分支**：`mac/ourtrail-explore-v3` · **证据档**：E3（模拟器像素 + SVG/组件读数），**不是**物理真机

## 0. 这次要证什么

用户给的是 390 宽的真机截图：72h 云层剖面 `剖面 0–5,250 m`、点 0 m、左上角一行 `▲ 窗外上方还有云带`，而云只画到 4,300 m。裁定（决定 A 四条）之后要证的只有一件事：

> 当数据里本来就有 8,000–9,700 m 的卷云时，**它必须画在图上**，而不是被窗裁掉、再用一行边注承认。

判据（全部由驱动脚本打印）：

1. 注入后仍在 ready（日期条非空）
2. 注入确实生效（窗范围 ≠ 注入前的真实数据窗）
3. 24/48/72 **三档显示窗逐字相同**（规划 horizon 固定 72，不随时长裁云）
4. 窗顶必须够到 **9,750**
5. 三档都**不再出现**「窗外上方/下方还有云带」
6. 图上真有灰阶云带（不是空图）
7. 此点在窗内（不出现「此点在剖面上/下方」）
8. 污染自证：三档 SVG 长度互不相同（period 真的生效）

## 4. 结论等级与缺口

- **E3（模拟器像素 + 读数）**：本页 72h 云层剖面在注入生产形状载荷后，高空卷云进入窗内、轴到 9,750、无裁切边注、点线在窗内、24/48/72 同窗。
- **未覆盖（不是通过）**：
  - **物理真机 NOT_RUN**（本轮只驱动了开发者工具模拟器）。
  - **真实数据外观 UNVERIFIED**：需要先部署 `trailApi`，真实返回里才会出现 400/350/300 hPa 这三层；此前真实数据最高只到 `剖面 0–5,500 m`。
  - **375 / 414 宽度**：只有 Node 几何判据（`meteogram-readability` §8/§9），没有像素。
  - **地图底图**：与本轮无关，仍未证。
- **本轮作废的尝试**（不在目录里，留在驱动脚本的 `DRIVER ERROR` 记录中）：第一次运行用 `mp.$()` 取组件，抛 `mp.$ is not a function`，未产出任何截图；第二次因门控字段写成了 v1 的 `dayCards`（V3 组件用的是 `ready`/`dayStrip`）而拿到 `gateReal=null`，并在 `page.onTab` 上报错——两次都在断言之前就停了，**没有把失败帧当证据留下**。
