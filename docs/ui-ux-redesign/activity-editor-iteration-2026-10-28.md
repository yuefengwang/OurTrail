# 发起活动：调研与小程序交互迭代

日期：2026-10-28。范围：原生小程序活动编辑器，不是另做 HTML 原型。不增加业务字段，不改服务端发布门槛，不涉及支付或云函数部署。

## 1. 调研依据与边界

本轮直接阅读三个产品当前的官方帮助页。依据是公开的产品流程说明，不是登录后逐屏操作测试，也不把帮助页的排版当成产品界面。搜索工具未返回可用正文后，改用浏览器读取官方页面。早期帮助页地址已失效的，使用站内搜索确认新地址。

| 产品 / 官方来源 | 核实的做法 | 本次借鉴 | 不照搬 |
|---|---|---|---|
| [Meetup · Creating an event](https://help.meetup.com/hc/en-us/articles/39790436736525-Creating-an-event) | 标题、日期时间、地点及找人说明；人数、报名起止等可选设置；可保存草稿、复制过去活动 | 按用户出行问题分组，草稿明确不是发布，可选内容按需展开 | 组织订阅、收费、重复活动、AI 生成等未有的能力 |
| [Strava · How Do I Create and Manage Group Events for My Club?](https://support.strava.com/en-us/articles/15401898-how-do-i-create-and-manage-group-events-for-my-club) | 开始日期时间与地点是必要信息；可选择已保存路线；路线与起始位置不同；人数上限、可发现性单独设置 | 集合点不藏在路线编辑后；路线复用为独立入口；公开范围清晰 | 其单日活动限制、运动配速分组、订阅门槛 |
| [Luma · Creating an Event](https://help.luma.com/p/creating-an-event) | 基础标题、日期、地点优先；地点地址与地图 pin 可分别调整；公开/非列表链接可见；报名审批、人数、创建后管理 | 基础填写优先，报名权限最后核对，强调链接可见不等于邀请制 | 主题商店、日历产品、售票与成员订阅 |

结论属于 OurTrail 的设计判断：不模仿售票后台，不新增多层设置页；在保留四个工作面的基础上，把必填信息集中，把低频可选信息归组，稳定每一屏的主操作。

## 2. 现状问题与保留项

改前基线：`1a9e4d3` 的 `miniprogram/pages/editor/editor.{js,wxml,wxss}`。本轮以基线源码和修改后源码核对结构；中断前放在临时目录的改前截图在续跑时已不可用，未把历史截图冒充本轮同条件对照。修改后的原生截图与读数见 `evidence/activity-editor-2026-10-28/`。

| 问题 | 可核事实 | 改法 |
|---|---|---|
| 开始填写之前读太多说明 | 页头口号、眉题、分区标题、必填说明、路线提示重复出现 | 短页头 + 四个短标签；字段说明只保留来源、格式和必要提醒 |
| 基础信息断裂 | 名称/时间在第 1 步，必填集合点在第 2 步的路线详情之后 | 集合点移至基本信息，地图取消和手动兜底保留 |
| 主按钮意图会变 | 任意步骤必填齐后，原「下一步」直接变「发布活动」 | 前三步主按钮始终下一步；齐备后有次级快捷核对入口，真正发布只在最后一步和确认层 |
| 第 4 步承担太多异类内容 | 报名规则、公开范围、费用、装备、风险混在一起 | 风险/装备归路线，图文/费用归介绍，最后一步集中核对和报名设置 |
| 发布前难定位回改 | 原确认主要是三行摘要，可选缺项只有统一出口 | 增加核对清单，逐项回编辑；集合点回到实际锚点；缺项可逐项补 |
| 报名提示可能与实际设置相反 | 关闭接受报名时，确认层仍写发布后可报名；审批 picker 未绑定当前选中值 | 显示真实开放状态、审核方式、可见范围；picker 高亮与当前数据一致 |

保留：本机草稿、服务器保存、资料门、图片上传与安全检查、GPX 元数据往返、路线阶段锁、可见性选择、本人参加的独立资料授权、并发版本控制与删除二次确认。不新增「徒步/休闲」业务类型，不借 UI 迭代偷偷变更轨迹必传规则。

## 3. 新流程

1. **基本**：活动名称 → 出发/结束/截止 → 集合地点与时间。可从路线开始或复制旧活动；时间估算标明需核对。
2. **路线**：路线库 / GPX → 路线和节点详情 → 风险 → 必带/建议装备。低频编辑保持收合。
3. **介绍**：正文与照片 → 可选简介、推荐理由 → 活动说明、费用、取消约定。
4. **发布**：实时核对时间/集合/路线/介绍 → 人数、审核、开放报名 → 公开范围 → 发布确认。

快速路径：基本信息齐备 →「直接去核对发布」→ 看清名额与可见范围 → 发布确认。快捷核对本身不保存到云端、不发布、不自动报名。返回修改保留原内容。

底部固定「保存草稿/保存修改」和唯一主推进动作，不再要求滚到表单底部找保存。已经发布的活动最终动作仍为保存修改，不提供重复发布入口。

## 4. 视觉与实现边界

- 复用 `app.wxss` 的森林绿、冷白纸面、文字层级、白卡、发丝线和触控尺寸；不添加全局 token、不修改其他页面主题。
- 首屏去口号和重复眉题；保留清晰步骤、输入标签和下一步。
- 路线来源为两块可点选择区；发布摘要为同一张卡内的可回改行，不再叠同级说明卡。
- 页面间信息移动同步更新缺项定位、路线自动生成集合点的跳转和可后补清单；未改变提交 payload。
- 仅改变小程序编辑器。没有新后端实体或命令，没有真实云端写入验收，没有发布或上传小程序。
