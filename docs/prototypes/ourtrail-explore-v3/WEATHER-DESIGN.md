# OurTrail · 山野天气原型设计说明

2026-10-26。入口：[weather.html](weather.html)。本轮交付是本地交互原型，使用 [weather-data.js](weather-data.js) 的确定性合成样本；没有连接天气服务，也没有改动生产小程序。

## 已确认的方向

用户明确选择：**先看专业数据：逐时预报、云层剖面和天气图。** 天气页首先帮助用户读懂某个地点、某个时刻的天气，出行解读和天相辅助阅读。沿用探索与活动详情的白底、清晰黑字和鲜明绿色选中状态，让图表承担主要视觉内容。

旧天气页的口号、长说明、日期卡、多个时间轴和结论卡占据较多阅读空间。本轮将其重新组织为四个视图，保留共同的地点与时间上下文。旧 `ourtrail-ui` 技能和天气设计文档只作为平台、业务及数据契约参考，不作为不可修改的审美边界。

## 页面结构与四个视图

共同页头显示活动地点、当前路线节点及海拔；日期条突出所选日期，默认选择活动日。“演示数据”入口解释样本、时区、单位及缺资料语义。向下阅读时，视图导航附带当前地点、节点和时刻，避免离开图表上下文。

| 视图 | 用户要看什么 | 本轮展示与交互 |
|---|---|---|
| 逐时预报 | 同一地点的天气如何随时间变化 | 温度与体感、降水量与概率、风速与阵风、高中低云量共用小时列；顶部读数与详细读数随小时游标更新 |
| 云层剖面 | 同一时间不同高度的模型云量 | 高度—时间灰阶图、节点海拔线、读取高度线、逐层数值；区分有效云量、无层资料和地形以下 |
| 沿途天气 | 同一时刻不同路线节点有什么差别 | 四个节点的示意图与列表；温度、降水量、阵风三种指标；选择节点后可查看该点逐时预报 |
| 日月天相 | 天文时刻与可能看到的现象有何区别 | 日照示意、日出日落、晨昏与暗夜条目；天相以“资料不足”说明缺什么，不制造窗口或星级 |

四视图使用一个选中地点、节点与时刻。内容通过平铺绘图区、对齐和分隔组织，不把每个指标包装成独立大卡片。绿色主要表达选中与节点参考，不能被读成“可以安全出发”。

## 时间、地点与导航

- 逐时与云层图提供 24 / 48 / 72 小时窗口，采用相同的小时列宽；包括 24 小时在内均可横向滚动，不将长时间窗挤成更小字号。
- 点按小时列、前后小时按钮或释放时间滑块后，选中线与读数同步更新；图表取得键盘焦点后也可用左右方向键选择小时。
- 视图切换、节点切换和沿途指标切换沿用选中日期与时刻；跨午夜游标同步显示对应日期。切换日期保留一天中的小时，接近样本末尾时不可用的长窗口受限。
- 切换预报跨度保留当前选中时刻，并以该时刻所在日期重设窗口起点。切换整个活动地点则重设为该活动的示例日期、第三个节点、13:00 与 24 小时窗口。
- 可搜索四个已有示例活动地点；这不是任意地名搜索或地理编码服务。
- 探索底部“天气”直达天气页。活动详情的天气入口带入活动标识；从活动进入时提供返回入口。浏览器历史记录保存天气页的选中状态与页面滚动位置；实际恢复结果以验证记录为准。

## 云层与缺资料的表达

本原型中的灰阶表示**离散模型高度的云量比例**。格子是样本层读数的视觉区间，不是连续实测的云底/云顶，也不据此推算真实云海边界。

- 绿色横虚线：已知的示例节点海拔；其下浅绿色区域表示地形以下。
- 琥珀横虚线：当前选择的读取高度，与节点海拔不是同一个概念。
- 斜线区域：没有可用模型层资料。缺层值为 `null`，不显示成 0% 或晴空。
- 青城后山“返回古镇”节点海拔为未知：仍能查看模型层云量，但不画节点海拔线、不画地形以下区域、不判断此点是否位于云中。
- 显示窗、资料覆盖范围与节点高度分别表达；扩大图的显示范围不会增加资料。当前样本的读取高度为 1,500–6,000 m、每 500 m 一层，并故意包含覆盖外空值，不代表真实数据源具备相同范围或分辨率。

这些展示约束保留了生产天气线的重要语义：无资料与无云不同，模型层值与真实云层几何不同，缺少可信海拔时不能给出地点相对云层的位置判断。本轮没有复制或修改生产云层、云海判据。

## 已完成的视觉状态与接入边界

样本涵盖毕棚沟、青城后山、措普沟、四姑娘山四个活动地点，每个四个示例节点。日期为 2026-10-29 至 2026-11-11，按北京时间 UTC+8 展示。温度为 °C，降水为逐小时 mm，风与阵风为 km/h，云量为 %，海拔为 m。名称用于评估真实文字长度，数值、节点位置、里程、海拔和天气变化均为虚构，不作为出行依据。

| 范围 | 本轮状态 | 正式接入时的要求 |
|---|---|---|
| 图表、小时选择、地点/节点/日期切换 | 已实现原型交互 | 对接真实响应，并验证加载、失败、过期与超出预报范围等状态 |
| 沿途独立读数比较 | 已实现合成样本交互，**属于接入提案** | 现生产每次获取当前单节点天气；需为各节点分别取数、管理缓存和失败状态，不能将一个节点的数据冒充整条路线 |
| 路线图 | 已实现节点示意 | 不含真实底图、导航、气象雷达或两点之间的连续天气；正式地图能力需单独接入 |
| 缺海拔、缺层与地形以下 | 已实现明确的视觉状态 | 延续真实数据来源、覆盖范围与缺失语义，不补造有利事实 |
| 日出日落、晨昏、暗夜与月面照明 | 已实现示意内容与排版 | 时刻及 23% 月面照明都是演示值，本轮未运行真实天文计算 |
| 天相 `unknown` | 已实现“资料不足”及缺失原因 | 这是完整的视觉状态，不是已完成天相计算；本轮未计算云海、光染、星空或银河窗口 |
| 天相有条件 / 已排除 | 帮助文案解释三态，未构建完整动态场景 | 对接生产同源判定：有条件显示窗口与依据，排除与缺资料分开，不另造总星级 |
| 独立坐标、地图选点、GPX 导入 | 本轮未实现 | 保留生产独立查询、观察点与轨迹组能力，后续设计其入口与状态 |
| 真实天气获取、缓存、天相算法 | 本轮未实现 | 继续采用既有数据与计算契约，不以演示生成器替换生产实现 |

本轮没有删除生产能力，也没有证明新原型已经覆盖整个生产天气模块。图片只出现在地点选择中作氛围示意，来源与许可继续见 [assets/sources.json](assets/sources.json)，不充当实时天气或实际路线照片。

## 官方参考与取舍

- [meteoblue · Meteogram 5-Day](https://content.meteoblue.com/en/time-dimensions/forecast/meteograms/5-days)：学习温度、云层/降水、风分图但共享时间关系的组织方式；不复制其桌面密度，不声称接入其预报。
- [Windy · Weather Academy](https://www.windy.com/articles/38548)：学习时间滑块、地点读数与天气图层的上下文关联；本轮沿途图仅为节点读数示意，没有使用 Windy 地图、模型或雷达。
- [Weathergraph 官方介绍与读图说明](https://weathergraph.app/)：学习逐时曲线表达变化、以同一图理解温度、降水、风和云量的方式；不复制品牌图形或数据源切换能力。

本轮选择明确的四视图，代价是跨主题多一次点击；共同状态用来降低切换成本。每小时保留可读宽度，代价是需要横向滚动。天相暂以真实的“未接入 / 资料不足”边界表达，避免用漂亮的窗口结论替代尚未实现的计算。

## 验证与证据
