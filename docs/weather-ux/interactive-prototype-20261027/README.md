本目录用于产品与开发协作审阅，演示天气查询、云层剖面和个人徒步行程的交互，**不代表小程序功能已经上线**。本次没有修改 `miniprogram/` 或 `cloudfunctions/`，无需部署 `trailApi`。

## 打开方式

直接用 Chrome 或 Edge 打开本目录的 `index.html`，无需启动服务或微信开发者工具。图标和提示组件的通用脚本由 CDN 加载，完整展示需要联网；天气内容不调用真实天气接口。

默认打开示例行程的「沿途天气」，点击一次经过进入该节点的详情。顶部返回按钮回到沿途总览，再返回天气首页。地图、经纬度进入相同的单点详情，不显示沿途空模块。

页面上方的「验收工具」不属于正式产品界面，可切换部分／全部云层缺测、加载、请求失败、超范围、离线与缓存过期，或模拟路线更新、权限失效、同步冲突和活动入口。原型基准日固定为 **2026-10-27**，时区为北京时间，默认行程为 10 月 31 日出发。

## 已确认的产品决策

1. 首期重点是时间 × 海拔的云层剖面，不包含地图卫星云图或大范围云层动画。
2. 多日徒步按天分组，用户可手动设置关键节点的预计抵达时间；计划时间不修改原始 GPX 记录。
3. 目标方案为登录后云端同步、同时保留本机缓存；本原型只模拟登录与云同步流程。
4. 天气与活动共用路线库，但天气行程单独保存，区分路线资产与具体出行计划。
5. 打开轨迹或行程默认展示「沿途天气」，点击节点后查看逐时预报、云层剖面和日月天相。
6. 从活动带入路线和出发时间后，形成个人独立天气计划，修改不回写活动。

第二轮用户选择 **ABAA** 并确认进入原型迭代：

7. 原始 GPX 的生产目标为完整私有保存，轻量轨迹与关键节点另存；原型只在本次页面内存中保留实际选择的原文件，未上传，刷新需重选。
8. **天气行程跟随最新路线，不固定创建时的路线版本。** 节点位置变化使用新位置，个人日期、经过顺序和时间不自动改变；新增点不自动加入行程；删除点保留原经过为待处理，不继续显示有效天气。按稳定节点 ID 对应，不按名称或数组位置猜测。访问失效明确标识，缓存不冒充最新路线。
9. 未登录可本机使用；首次绑定账户时确认导入，只有主动保存资产入云，最近查询仅本机；冲突保留双方，不静默覆盖。这里的账户、同步和冲突均为模拟。
10. 首期国内徒步、明确北京时间；不承诺海外当地时间和夏令时行程能力。

### 路线节点与每次经过

- 路线记录固定关键节点；行程保存多次经过的独立标识、关联节点 ID、天数、抵达／出发类型和可空时间。同一营地可在 D1 抵达、D2 出发，亦可重复经过。
- 原型中 `pointSnapshot` 仅用于节点被移除时展示待处理记录，不用于锁定路线或让正常天气查询继续读旧位置。
- 编辑允许增加、移除、重新选择、上下调整经过顺序；时间逆序或仍有被移除的节点时阻止保存。取消不改原计划，返回时确认是否丢弃编辑。
- 13:30 等非整点计划明确参考相邻小时；浏览日期与计划时刻分开，浏览不修改计划。未安排时间仍可查询节点；超范围不改变计划日期。

## 建议审阅路径

- **沿途天气**：切换 D1 / D2，查看每次经过；进入节点后只有逐时、云层、日月三项，返回恢复沿途层级。
- **云层剖面**：切换 24 / 48 / 72 小时，点按／拖动／前后小时／直接选时；切换高度窗口，对照显示范围、有效范围和地点海拔。用验收工具切到部分缺测，选择 09:00 检查遮罩与缺测读数。预报末端不允许超出可用时长的窗口。
- **个人计划**：编辑日期、添加同一营地的再次经过、选择抵达／出发、移动顺序、留空时间；逆序阻止保存；取消不改原计划，复制生成独立副本。
- **单点查询**：返回首页，地图选点或手动输入经纬度；单点不显示「沿途天气」，可加入常用地点。
- **路线导入**：使用示例或本机 GPX，筛选／重命名候选节点；原始记录时间只作参考，不填入出行计划。实际选择文件后，可在路线信息中只读查看未被改写的原文件；刷新后准确提示仅剩元信息。
- **资产管理**：分别管理地点、路线、行程；列表右侧更多入口可重命名／编辑／删除。删除二次确认，删除计划不删路线，被行程引用的路线不可直接删除。最近查询可独立清除，不影响主动保存。
- **路线更新**：在示例行程点击验收工具的「模拟路线更新」，检查旧时间未变、新补给点未自动加入、D2 垭口已移除但经过记录仍保留；在编辑中主动替换或移除该经过。
- **同步**：从右上保存状态进入；模拟登录后仍需确认导入，可以暂不导入；离线保持待同步；用验收工具制造冲突，保留两版生成独立副本。

视觉采用当前活动页的森林绿与冷白纸面方向。原型的图表和布局用于确认信息层级、交互与可读性，不是小程序组件的直接替代品。

## 演示边界

- 天气、云层和日月天相均为**样例数据**，不是实时预报，不能作为出行决策依据；样例日期不会随实际日期自动滚动。
- 地图选点是交互模拟，没有真实地图 SDK、搜索、定位或坐标转换服务。
- 登录、云同步、共用路线库与活动导入展示的是目标流程，没有接入真实账户、数据库、活动或路线 API。浏览器的演示状态保存不等于生产级离线缓存或跨设备同步。
- GPX 仅在本机读取，文件须不超过 2 MB，最多 6 个候选点；优先航点／路线点，否则抽样轨迹点。此限制只用于原型，不是对现有小程序 8 MB／12 节点能力的修改。原始文本只留在页面内存，不写入会话状态，不执行云存档、真实路线统计或分段业务。
- 缺海拔不画地点线；超出有效高度不判断晴空；部分云层缺测用遮罩且对应读数为空，完整缺测不画云。图形展示窗口与有效数据范围分离，灰阶沿用生产图的 10／25／50／75／90% 档位，但数据仍为合成样例，不能与不同地点截图比较天气准确性。
- 加载、失败、离线缓存、缓存过期和同步冲突均可通过明确标为演示的入口触发，不是真实故障。过期天气不显示假结果，资产不随天气缓存一起删除。
- 行程编辑最多展示 D1–D7，原型最多展示 72 小时图，都是演示范围，不新增生产业务限制。浏览器原型状态受会话 16 KiB 上限影响，不是可靠离线资产库；超限提示本次状态未持久保存。
- 验证范围是浏览器原型，不包含微信真机验收、真实天气精度、云同步与活动权限验证。

## 运行检查

在已有 Node.js、Playwright 及其 Chromium 的环境中，从仓库根目录运行：

```sh
node docs/weather-ux/interactive-prototype-20261027/verify.cjs
node tools/check.js
node tools/check-handlers.js
git diff --check
```

不要为本原型向项目添加 `package.json`、锁文件或 `node_modules`。可复用仓库外的 Playwright 安装，并通过环境变量指定路径：

```sh
PLAYWRIGHT_MODULE_PATH="/absolute/path/to/node_modules/playwright" \
CHROME_EXECUTABLE_PATH="/absolute/path/to/chrome" \
node docs/weather-ux/interactive-prototype-20261027/verify.cjs
```

`PLAYWRIGHT_MODULE_PATH` 和 `CHROME_EXECUTABLE_PATH` 均可省略；省略时使用 Node.js 默认模块解析和 Playwright 默认 Chromium。截图默认写入系统临时目录，可通过 `WEATHER_QA_OUTPUT` 指定仓库外的输出目录。脚本失败时退出码为非零，成功时打印实际检查数与截图路径。

覆盖内容包括默认沿途入口、节点与图表切换、读数联动、320 / 375 / 390 / 414 px 布局、标签碰撞、预报范围、时间校验、独立复制、收藏与导入保留、缺海拔/缺云层/离线状态以及浏览器运行时错误。

2026-10-27 第一轮入库时实测：**29 项浏览器检查全部通过**，浏览器运行时错误为 0。此项为历史基线，不能替代第二轮验证。第二轮验证及交付边界见 [REVIEW.md](REVIEW.md)。
