# Meteoblue Integration Options —— 接入可行性研究（F 交付物）

日期：2026-10-05 · 结论先行：**维持自建 meteogram（方案 A），把 Meteoblue 定位为未来的第二数据源/交叉校验（方案 B 预埋适配层），web-view 嵌入（方案 C）在本仓主体下不可行。**

本调研只做桌面与官方文档检索，未爬取网页数据、未解析 DOM、未绕过任何授权。

---

## 1. Meteoblue 对户外用户的价值（为什么值得研究）

- **Meteogram 的信息架构本就是徒步圈的行业习惯**：温度线/降水柱/多层云量/云层高度带沿时间轴铺开，
  一张图回答「雨何时来、云在几米、我几点经过」。P1 文档已确认这一习惯并据此设计现状页。
- **多模型集合**：meteoblue 聚合 NEMS/MPI/ICON 等 30+ 模型做后处理，山区的低云与降水
  情景判断是其强项——这正是「云层高度 ±300–600 m」这一单模型弱项（P1 §5.3）最想补的地方。
- 值得学的是**信息架构与变量组织**（见 §4），不是它的品牌与界面。

## 3. 微信小程序侧的平台约束（决定性）

1. **web-view 权限**：个人主体小程序**没有** `web-view` 组件权限；企业主体也只能打开
   **自有备案业务域名**下的页面。`meteoblue.com` 不是我们的域名 → **方案 C 直接出局**
   （与 P1 文档 2026-09-28 的结论一致，本次复核仍成立）。
2. **`<image>` 加载远程图**：`<image src>` 不受 downloadFile 域名白名单限制，技术上可显示
   Image API 的图。但 meteoblue 免费图片条款要求**可见署名 + 可点击回链**——小程序内
   图片无法携带可点击外链（跳外链需 web-view），署名回链义务**无法如实履行** → 合规风险。
   Image API 商业套餐（付费、可谈条款）可以解决授权，但€2,400/年起 + 图片不可本地化
   （英文界面、不可改色、不可叠加 OurTrail 节点/云带/天相标记）→ 体验与可维护性都差。
3. **API 数据接入无平台障碍**：云函数 https 外呼（现有 Open-Meteo 代理同一模式）+
   30min 缓存 + 下发 JSON，key 存云函数环境变量。这是唯一顺畅的路径。

## 4. OurTrail 应该学什么、不该复制什么

**学（已经体现在 weather-ux-design.md）：**
- 逐时连续序列沿一条时间轴铺开（温度/降水/云/风同轴对齐），而不是并列数字卡；
- 云量按**高度层**表达（低/中/高 + 垂直剖面），直接回答「云在脚下还是头上」；
- 昼夜/晨昏与时间轴视觉绑定；
- 多变量对齐比较：用户自己结合经验下结论——这与「事实 → 解释」的产品原则同构。

**不复制：** 品牌与配色（OurTrail 有自己的 design system）、英文界面、桌面端密度
（375px 一屏 24h 才是移动真解）、其「多模型概率」话术（无多模型时不可伪装）。

## 5. 三个方案

### 方案 A（推荐·现状延续）：自建 meteogram，Open-Meteo 数据
- **成本**：0（数据免费、署名义务=页脚文字，已合规）。
- **开发难度**：中（即本设计规格的实现量）。
- **法律/授权**：CC BY 4.0 署名即可，无商业限制（当前零金额产品安全）。
- **体验**：唯一能叠加 OurTrail 独有层（节点海拔线、云层带、天相窗口、中文）的方案；全中文、可定制。
- **可维护性**：引擎全在本仓、65+ 例纯函数测试钉住阈值。
- 短板：单模型；云层高度 ±300–600 m；无集合预报。

### 方案 B（未来增强）：Meteoblue 作为第二数据源/交叉校验
- **形态**：云函数 MeteoblueProvider（Free Weather API 起，适配 `NormalizedWeatherData`），
  与 Open-Meteo 并跑；UI 先用做「多模型一致性」提示（如两源低云均 ≥80% 才升云海一档），
  远期可切换主源。
- **成本**：首年免费（10M credits），后续按量付费；Premium €2,400/年起。
- **开发难度**：低-中（适配层已在设计规格阶段 3 预埋；主要是 credit 计量与缓存策略）。
- **法律/授权**：API 数据商用需其套餐许可（Free API 条款偏试验用途，商用前必须书面确认条款）。
- **时机建议**：等 V1 验证「天气/天象是用户留存点」之后再启动；当前阶段**只建适配层不接**。

### 方案 C（排除）：web-view 嵌 meteoblue / 官方 widget
- 个人主体无 web-view 权限；企业主体也需自有备案业务域名；widget 是 web 嵌件。
- **不可行，不再评估。**

## 6. 推荐路径

1. **现在**：方案 A（本设计规格 + 原型），页脚署名 Open-Meteo。
2. **现在（零成本预埋）**：`WeatherProvider → NormalizedWeatherData` 适配层 + `provider{}` 元信息（规格阶段 3）。
3. **未来（有留存数据后）**：按方案 B 注册 Free Weather API 试点多模型交叉，商用条款书面确认后再扩大。
