## 实际入口与功能

| 入口 | 小程序实际行为 | 实现文件 |
|---|---|---|
| 底部「天气」→ 地图选点 / 经纬度 | 同一单点详情，查询与主动保存分离；校验空坐标、范围、海拔，WGS-84 可转换为 GCJ-02；未知海拔不填 0 | `miniprogram/pages/weather-hub/` |
| 单点 / 节点详情 | 逐时预报、云层剖面、日月天相三个标签；默认云层；不显示单点的沿途空模块 | `miniprogram/pages/weather/` |
| 天气 → 导入 GPX | 保留或移除候选关键点，复制原始 GPX 到微信本机文件区，原字节不改；保存后进入沿途总览 | `weather-hub.js:onGpxApply` |
| 天气 → 从路线库选择 | 调现有 `readRoutes`，按账户已有权限读取路线；进入独立个人天气行程 | `weather-hub.js:onRouteLibrary` |
| 本机轨迹 → 存入路线库 | 二次确认后调用现有 `route.create`，创建私有路线；仅节点和轻量折线上传，原始 GPX 不上传 | `weather-hub.js:onSaveRoute` |
| 活动详情 → 天气 / 路线详情 → 沿途天气 | 默认进入新 `pages/weather-plan`，不是先进入某个点的云图 | `activity.js:onWeather`、`route.js:onWeatherPlan` |
| 沿途天气 → 安排行程 | 按天、手动时间、抵达 / 出发、重复经过、重新选点、排序、删除经过；保存到本机 / 复制 / 取消 | `miniprogram/pages/weather-plan/` |
| 沿途天气 → 节点详情 | 以节点稳定 ID 和浏览或计划时刻进入详情；非整点按所在小时读数，不声称分钟级预报 | `weather-plan.js:onNode` |

地点、原始轨迹、个人行程、最近查询分别保存。最近查询只留本机，不自动加入常用地点。删除本机条目需确认；有行程引用的本机轨迹不能直接删除。行程日期与浏览日期分开，历史 GPX 时间不自动成为本次抵达时间。

真实接口链路为现有 `utils/api.js` → `readRoutes` / 活动 `read` / `getWeatherByPoint` / `getSkyContext`，没有把原型样例天气植入生产页面。

## 云层图与视觉

- 保留原有连续灰阶云层渲染，10 / 25 / 50 / 75 / 90% 对应分层云量，不是云概率或卫星云图。
- 新增自适应、0–4 km、3–7 km 显示窗；明确位势高度近似海拔，不是离地高度。显示窗不参与云层位置判定，参考线仍标海拔来源。
- 部分缺测不再用最近小时补齐；按小时、有效高度覆盖外画斜纹，读数明确缺测，不判晴空。全无垂直数据时给空态和重试，逐时天气仍能查看。
- 点按、横向拖动、前后小时按钮、直接选时共用选中状态；天相「看图」会切到实际图表标签再定位，不滚向隐藏图表。
- 2 m 温度、10 m 风与云层纵轴的语义分开说明。总降水已包括阵雨，修复重复相加及读数缩放错误；未知值保持缺测。
- 页面外壳复用活动页背景、森林绿、品牌栏、按钮、表单与状态组件；天气变量保留各自语义色。行程页使用较紧凑间距，避免首屏只有操作区、看不到节点天气。

## 路线更新与权限

1. 保存行程引用稳定节点 ID；重开会读取最新可访问路线，不按名字或数组下标猜节点。
2. 节点位置更新使用新位置；个人日期、时间、经过顺序不自动改变；新增点不自动加入。
3. 已删除节点保留为待处理，不继续查旧坐标；替换或移除前阻止再次保存。路线权限撤回时清空天气行，不用本机缓存冒充可访问路线。
4. 活动会带入出发日期，并保留原出发时刻作为安排提示，但不会给所有节点自动填时刻，也不会回写活动。
5. **当前权限限制**：活动参与者可能能看活动快照，却无权限看私有路线原件。活动入口仅在原件返回 `FORBIDDEN` / `NOT_FOUND` 时使用其已获授权的活动快照，并显式标注“活动当前路线快照，未取得路线库原件权限”。网络失败不走这条回退。此分支不等于“始终跟随路线库最新原件”，本轮未扩大服务端权限。

## 用户自验顺序

1. 微信开发者工具打开本仓库并重新编译，底部选「天气」。新首页应看到“查一个地点 / 查一段行程”。
2. 输入一个地点，先看云层；切高度窗、小时、逐时和日月标签。缺数据时必须看到解释，不应是装饰性云团。
3. 导入 GPX 或选择你有权限的路线，应先看到“沿途天气”；点“安排行程”，分别填写第几天、几点经过。
4. 保存后回天气首页，从“个人天气行程”再打开；点击某节点，检查日期 / 小时与计划一致。
5. 活动与路线详情的天气入口也应进入沿途页；编辑个人计划后活动本身不变。
