## 一、这一轮是从上一轮的哪一句话里长出来的

第十轮用户原话点名了六个现象：「彩虹、晨昏光染、银河、星空、蓝调、黄金」。
沉默闸收掉了前四个（结论卡层面），**蓝调与黄金没有动**——因为它们不是概率判断，
是太阳高度角穿越 -6°/-4°/+6°/0° 的客观时刻，任何天气都发生。

我上一轮在报告 §九 写过一句"仓库里没有可追溯的『斜射暖光被挡住』口径"。
**那句话说过头了，本轮收回**：口径就在 `sky.hourMarks` 的光染判据里，
注释原文是「低云少（光能到山体）」，即 `c.low < 40`。我当时把它和彩虹那道闸
（`low < 40 && (mid+high)/2 < 30`，说的是"看不看得见太阳盘面"）混成了一句。
两句话确实不同，但**前一句正是黄金时刻要的那一句**。

所以用户选的 A 落地成：**时间一条不删，只在当时低云达到"光到不了山体"的程度时，
给那两行补一句事实**。

| `tools/weather-v2-test.js` §2b | 14 条新断言（见 §五） |

文案分岔（措辞按窗口物理不同）：

- 黄金：`斜射暖光开始（当时低云 100%，斜射暖光可能到不了山体）`
- 蓝调：`天空最蓝的十几分钟（当时低云 100%，天空可能只发灰不发蓝）`
- 原本没有 sub 的"昏"两条：后缀单独成行，不硬造前半句。

三条纪律：① **后缀是"加"上去的**，原话一个字不改写（断言盯着前缀）；
② 缺云量读数 ⇒ 不加话（`Number(null) === 0` 会把"没有读数"印成"低云 0%，光好"，那是凭空造有利事实，
所以 `lowCloudAt` 只认 `typeof === 'number'`）；
③ 卷层云不误伤——判据只看低云，全天 95% 中高云 + 低云 5% 的一天**不加后缀**
（合成场景里就有这一组，读数 0 处后缀）。

## 三、"单源"这次是真的可测

`LIGHT_LIMITS` 是**导出的对象**、消费方按引用读（铁律 31③）：
影子测试把 40 改成 95 ⇒ 同一份"低云 60%"的数据，光染标记数**变多**、彩虹标记数**变多**、
窗口后缀**归零**——三处一起动才算引用同一个数；任何一处不动，就说明那里还抄了一份自己的 40。
还原后逐项相同（防止两个零恰好对上）。另配一条静态门：`agenda.js` 里不得再出现 `<40 / >=40` 这类字面量。

一条如实账：**P7 第一次是漏网的**，原因不在判据而在夹具——我的"缺读数"用例只铺了一行 `00:00`，
却去查 `06:40` 的低云，`lowCloudAt` 查无此小时直接返回 null，那条断言因此**从未真正走到 null 分支**
（假绿）。改成铺满 24 小时的 `cloud: {low: null}` / `cloud: {}` 两份夹具后，P7 才会红。
教训：缺输入类断言必须让"被查的时刻"真的落在夹具覆盖的小时里，否则测的是"查不到"而不是"判不出"。

## 八、发现但**没有**动的东西（留裁决）

时间轴上「20:03 天文暗夜始」的 sub 写的是**「银河与深空窗口」**——满云那天银河卡已经被沉默闸收掉了，
这一行却还在把暗夜说成银河窗口，属同一类"把不可能包装成建议"。
它和黄金/蓝调不同：暗夜时刻本身是客观的（保留没争议），但那半句 sub 是一句**机会主张**。
最小修法是把这半句也交给三态口径（暗夜晴空 0% 时改说「中高层云偏厚，当晚看银河不划算」或干脆只留「天文暗夜开始」），
一行文案 + 一条断言的事，等用户点头再动。
