## 二、根因归层（一句话）

**分数被同时当成了两件事用**：`sky.js` 的 `score` 只回答"多有戏"，但页面把"要不要出现"也交给了它——
低分卡照样排版、照样给方位、照样给"为什么？▾"证据行。判据本身是对的（星空/银河确实在满云日判了 0 晴空率），
错的是**呈现层没有"判过不成立"这个概念**。

所以本轮不是调阈值，是把「出现 / 沉默」从分数里拆出来，变成一个显式字段。

## 三、口径（三态，不是两态）

`miniprogram/utils/sky.js:97`

| verdict | 含义 | 页面 |
|---|---|---|
| `possible` | 必要条件成立，有戏 | 出卡 |
| `excluded` | **判过了**，必要条件不成立 | **沉默** |
| `unknown` | 缺输入判不出（无可信海拔 / 无暗夜小时） | **仍出卡**，并说明缺什么 |

第三态不是装饰：铁律 26② 定过「无法判断写成"晴空"就是凭空造否定事实」，反过来同样成立——
把"没数据"当成"不可能"而减卡，是把弃权冒充成结论。因此 `isSilent()`（sky.js:101）**只对 `excluded` 为真**，
缺字段一律失败开放（不沉默）。

每条沉默的出处（都是**已有分支**起名，不是新判据）：

| 现象 | 沉默条件 | 复用的一句判据 |
|---|---|---|
| 晨昏光染 | 晨昏窗口内没有一小时满足"低云少 + 无降水" | sky.js:239 |
| 云海 | 有成层云带，但此点不在带顶之上 | sky.js:318 |
| 云海 | 整天没有 ≥80% 的成层云带 | sky.js:287 |
| 星空 / 银河 | 天文暗夜里"中高层云少且无降水"的小时数 = 0 | sky.js:349 / 392 |
| 银河 | 不在银心季（客观天文事实） | sky.js:362 |
| 彩虹 | 没有任何一小时同时满足"太阳照得出来 + 有水分" | sky.js:405 |

弃权（`unknown`）的出处只有两处：无可信海拔（sky.js:282）、没有暗夜小时（sky.js:331 / 366）。
客观时刻卡（黄金/蓝调/日出日落）**永远 `possible`**：它是钟点，不是概率判断（sky.js:443）。

## 九、没做的两件事（留给裁决）

1. **黄金时刻 / 蓝调时刻**：本轮**未动**。它们是 `astro.photoWindows` 的客观穿越点（太阳 +6°~0°、−6°~−4°），
   按现有口径不是概率判断，页面里由日照轴与 Agenda 表达（`light` 卡本来就不出卡）。
   真要按天气裁掉它们，需要先有一个"**斜射暖光/蓝天漫射被云挡住**"的可追溯口径——
   仓库里现成的 `low < 40 && (mid+high)/2 < 30` 是给"看到太阳盘面"用的，
   它对卷层云会判"遮死"，而卷层云恰恰是日落最好光的一部分；拿它裁黄金时刻会造出**假否定**。
   选项：A 保持原样（只当钟点用）／B 在 Agenda 那两条 sub 上加"当时有云"的事实后缀（不裁时间）／C 定义新口径并给样本（要走 R1 那套口径归属流程）。
2. **银河那颗来自"月黑"的星**：第九轮登记未改。满月 + 满云那天银河现在整卡沉默了，
   这条读数不再可见；月照项本身是否该继续加分，仍属产品裁决。
