# 设计文档：活动详情页路线地图可视化

日期：2026-09-28
状态：已实现（待真机联调；§9 两个待确认问题按默认方案执行）
影响版本：V1（编辑器 + 活动详情），为 V2 路线库打地基
相关模块：GPX 导入（editor）、路线数据模型（cloud schema）、活动详情页（activity）

---

## 1. 背景与目标

GPX 导入功能落地后，路线节点的经纬度数据**已经在产生并入库**，但界面上无处可看：详情页路线 timeline 只渲染节点名和类型（`activity.js` 的 `points` 映射丢掉了 coordinates）。用户确认选择方向 B——**在活动详情页做路线地图可视化**。

目标：

1. 参与者在出发前能看到**真实路线形状**（轨迹线）+ 节点/上车点位置，替代纯文字 timeline 的想象；
2. 对"途中清点、进度确认"场景提供空间参照；
3. 一键导航到起点/上车点（`wx.openLocation`），出行当天的高频动作。

产品对齐：V2 文档「路线升级：从活动文本中的位置点，升级为有轨迹、版本、节点、风险点的路线库」——本设计把"轨迹"首次引入数据模型，是 V2 路线库的第一块地基。

## 2. 关键决策

### 2.1 坐标系统一为 GCJ-02（本设计的前置修复）

现状盘点（已逐一核实）：

| 数据来源 | 坐标系 |
|---|---|
| 编辑器地图选点 `wx.chooseLocation` | GCJ-02 |
| 签到/位置上报 `wx.getLocation({type:'gcj02'})` | GCJ-02 |
| **GPX 导入** | **WGS-84（异类）** |
| `map` 组件 / `wx.openLocation` | 要求 GCJ-02 |

GPX 标准坐标是 WGS-84，直接上图会**系统性偏移 100~700 米**（中国境内）。全项目尚未上线（云函数待部署、无存量用户数据），是统一坐标系的零成本窗口期。

**决策：存储约定 = GCJ-02。GPX 导入时在 `utils/gpx.js` 内做 WGS-84 → GCJ-02 转换**（纯函数，node 可测）。编辑器地图选点和getLocation 链路不动。

- 转换算法：标准纠偏公式（公开算法，误差 ±1~2 米，徒步场景可接受）；中国境外坐标原样返回（算法内置越界判断）。
- 详情页 `wx.openLocation`、`map` 组件直接消费库存坐标，不再转换。

### 2.2 数据模型：routeSnapshot 增加可选 track 字段

地图要画出真实路线形状，只有 ≤12 个节点的折线是不够的（会变成直线段连接）。当前 GPX 解析后轨迹点被丢弃，只保留里程/爬升。

**决策：`routeSnapshot` 增加可选字段 `track`**：

```js
// cloudfunctions/trailApi/domain/schema.js 新增
const TrackPoint = specObj({ lat: specNum(-90, 90), lng: specNum(-180, 180) })
// RouteSnapshot 与 Route 均增加：
track: specOpt(specArr(TrackPoint, 2, 200)),
```

- **上限 200 点**：GPX 原始轨迹可达数万点，入库前按累计里程均匀采样到 ≤200 点（gpx.js 已有同思路的节点采样逻辑，新增 `simplifyTrack` 纯函数）。200 点 polyline 渲染流畅，单活动增量 <1KB。
- **schema 是 strictObject 语义（多余键被拒）**，RouteSnapshot 和 Route 必须同时加，否则活动创建/编辑直接校验失败。
- 私有路线落库（`domain/activity.js` 的 `persistPrivateRoute`）是对 routeSnapshot 的深克隆，加字段后自动携带，无需改动。
- **无 track 的降级**：手动选点路线、历史草稿没有 track——地图退化为节点间的虚线连接段（`dottedLine`），节点 marker 不受影响。这保证功能永远可用、只是形状保真度不同。

## 3. 详情页 UI 设计

### 3.1 位置与布局

「路线与集合」区块内，**地图卡在 timeline 之上**：

```
路线与集合                    [天气参考]
┌────────────────────────────┐
│                            │
│         map 260px          │   ← .map-card
│                            │
└────────────────────────────┘
01 · 起点
   青城后山停车场          [导航]
02 · 途中节点
   ……
```

- 高度 **260px**，宽度撑满卡片；外层 `.map-card` 用 `border-radius: 14px` + `overflow: hidden`（与 `.card` 一致的圆角语言）。注意：map 是原生组件，低版本基础库非同层渲染时圆角可能失效，**属可接受降级，不做 hack 补偿**。
- **空态规则（渐进披露）**：所有节点和上车点均无坐标时，**整块地图卡不渲染**，timeline 原样保留——不渲染空地图，不显示"暂无地图"占位。
- 部分定位（有坐标节点 ≥1 个）即渲染地图，只上已定位的点。

### 3.2 地图元素视觉规格（全部取自现有 token，不发明新色）

| 元素 | 规格 |
|---|---|
| 轨迹 polyline（有 track） | `#163E35`（--forest），width 4，`arrowLine: true` |
| 降级连接线（无 track，≥2 定位点） | `#8C9791`（--control-line），width 2，`dottedLine: true` |
| 起点 marker | forest 实心圆点，label 显示序号 `1` |
| 途中节点 marker | 白底 + forest 描边圆点，label 序号 |
| 终点 marker | leaf `#D6EA8A` + forest 描边（品牌高亮色收尾，在任意地图底色上都跳） |
| 上车点 marker | info `#346583`（信息蓝=车辆语义），label 不编号，靠 callout 区分 |
| callout | 白底、forest 文字、圆角 8、`BYTAP` 触发，内容 = 节点名 + 类型（"起点 · 青城后山停车场"） |

marker 图标用**预生成 PNG**（`miniprogram/assets/markers/*.png`，约 6 个小图：起点/途中/终点/上车点 × 普通/选中两态）。微信 map 的 `marker.iconPath` 不支持 base64，必须本地文件；由 `tools/gen-map-markers.js`（node 脚本，纯色圆 + 描边）生成入库，避免手绘素材依赖。序号不用画进图里，用 marker 的 `label` 属性（白底 forest 字）叠加。

**不在地图上叠加任何自定义 UI**（无悬浮按钮、无图例条）。map 是原生组件，同层渲染依赖较新基础库，叠加普通 view 在低版本会被原生层盖住——设计上直接规避。

### 3.3 交互

1. **marker 点击** → 显示 callout（默认行为，零成本）。
2. **timeline 行点击**（有坐标的节点）→ 地图 `include-points` 重算为中心到该点的视图 + 该 marker 切换选中态图（放大版）；再点一次还原。让"清单"和"地图"互相指认，这是清点场景的核心动作。
3. **导航**：timeline 中有坐标的节点行、以及有坐标的上车点行，右侧加「导航」文字按钮（`.button.text`）→ `wx.openLocation({latitude, longitude, name, address})`。openLocation 拉起内置腾讯地图，无需任何隐私声明或 key。上车点的导航价值最高（司机/拼车场景）。

### 3.4 数据组装（activity.js）

```js
// 伪代码：reload 后从 routeSnapshot 组装
const located = a.routeSnapshot.points.filter(p => p.coordinates)
const markers = [...节点 markers（含选中态）, ...pickup markers]
const polyline = hasTrack
  ? [{ points: track, color: '#163E35AA', width: 4, arrowLine: true }]
  : located.length >= 2
    ? [{ points: located, color: '#8C9791AA', width: 2, dottedLine: true }]
    : []
// include-points: 全部 marker 坐标（四角外扩 ~0.5% 纬度差做留白，该属性无内边距参数）
```

色值带 AA 透明度（85%）缓解 polyline 压盖路网底图的生硬感。视口适配用 `include-points`，不做手动 scale 计算；单点时 `latitude/longitude` 直接给该点，scale 14。

## 4. 编辑器侧变更（GPX 导入链路）

1. `utils/gpx.js` 新增两个纯函数：
   - `wgsToGcj(lat, lng)`：标准纠偏 + 境外原样返回；
   - `simplifyTrack(points, max=200)`：按累计里程均匀采样；
   - `parseGpx` 返回值增加 `track`（已转换、已采样、已含首尾点）。
2. `editor.js onGpxApply`：`form.track = parsed.track`；`buildInput` 写入 `routeSnapshot.track`；`toForm` 读回（草稿往返不丢）。track 对用户不可编辑，纯透传。
3. 手动选点路线保持无 track（降级虚线），不做合成。
4. 示例路线（useSampleRoute）：可选给一条小的合成 track（青城后山），让无 GPX 的用户体验完整效果——实现时顺手做，失败不阻塞。

## 5. 平台约束清单（实现时逐条对照）

- [ ] marker `iconPath` 必须本地 PNG（base64 不支持）；`label` 做序号。
- [ ] 不在 map 上叠加普通 view/按钮；callout 用原生。
- [ ] `include-points` 无内边距参数，用外扩点做法留白。
- [ ] polyline 颜色格式 `#RRGGBBAA`。
- [ ] `wx.openLocation` 无需隐私声明；`requiredPrivateInfos` 已含 getLocation/chooseLocation，无需改 app.json。
- [ ] 低版本基础库非同层渲染 → 圆角可能失效，接受降级，不做 cover-view 补偿。
- [ ] schema 严格模式：RouteSnapshot 与 Route 同步加 `track`，缺一处则 activity.create/edit 全量校验失败。

## 7. 验收标准

1. GPX 导入 → 保存 → 详情页地图显示**真实轨迹形状**，节点/上车点齐全，真机上 marker 位置与实地偏差在正常纠偏范围内（<50m 级）。
2. 手动选点路线（无 track）→ 地图显示节点 + 虚线连接，无报错。
3. 全部无坐标的路线 → 地图卡不渲染，页面与现状一致。
4. timeline 行点击 ↔ 地图定位联动可用；起点/上车点「导航」拉起内置地图。
5. 旧草稿（无 track 字段）打开编辑器再保存，不触发 schema 校验失败（specOpt 兼容缺省）。
6. `tools/gpx-test.js` 新增用例全绿；云函数 smoke 通过。

## 8. 范围外（明确不做）

- 编辑器步骤 2 的路线预览小地图（二期可加，数据就绪后是纯展示工作量）。
- 路线库、路线版本管理、分段天气（V2 范畴）。
- 实时位置追踪、离线地图。
- 首页活动卡片上的迷你地图。
