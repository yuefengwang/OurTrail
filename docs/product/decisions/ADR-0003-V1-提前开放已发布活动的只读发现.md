# ADR 0003：V1 提前开放已发布活动的只读发现

日期：2026-09-28  
状态：已确认  
影响版本：V1（能力自 V3 提前）  
相关模块：活动发布、活动列表、隐私投影、信任与安全  
修订对象：[ADR 0001](ADR-0001-V1-允许任何人创建私域活动.md) 第 2 节的「不做公开活动广场」在**分发侧**的推论

---

## 1. 决策

V1 在小程序内提供**只读发现页**，让任何已完善资料的微信用户都能主动找到已发布的活动，无需先收到私域链接。

- 新增读取请求 `kind: 'discover'`，经既有 `read` 动作返回，无需新增云函数路由；
- 收录范围：`phase` 不属于 `draft` / `cancelled` / `archived`，且 `startAt` 尚未到达（即 `published`、`gathering`、`active`、`closing` 中尚未出发的活动）；
- 排序：按 `publishedAt` 倒序，同值按 `startAt` 升序；
- 支持按活动名、路线名、描述做关键词搜索，服务端过滤；
- 单次返回上限 50 条；未完善资料时返回 `AUTH_REQUIRED` 并引导补全。

私域分享（微信聊天、群聊、小程序卡片）**仍是主要传播方式**，本 ADR 只是补上一个兜底入口，不改变主路径。

## 2. 修订 ADR 0001 的理由

ADR 0001 的决策是「创建端完全开放」，「私域传播」是它推导出的**结果**，而非它要回答的问题。两者组合产生了一个副作用：

> 活动可见性的唯一钥匙是邀请链接。

实现层把这个推论固化得比 ADR 更彻底：活动文档上没有 `visibility` 之类的可发现性字段，`home` 列表只按关系（所有者 / 本人报名 / 现场协作 / 车辆联络）过滤，唯一的对外通道是客户端本地记录的「最近打开过」。结果是**已发布的活动对任何未收到链接的用户完全不可见**，且默认页签还会把「打开过但未报名」的活动过滤掉。

这与「活动发布后应能被主动找到」的预期直接冲突。根因是治理问题而非编码问题：`00-产品愿景与版本路线图.md` 第 10 节「待继续确认的问题」第 1 条「V1 是否只服务微信私域分享，不提供任何公开活动列表」长期未销账，ADR 0001 单方面选择了「不提供」并标记为已确认，路线图未同步。预期与实现因此长期分叉。

本 ADR 正式关闭该问题：**V1 提供只读发现，公开活动广场本身仍不做。**

## 3. 本次不改变的部分

以下 ADR 0001 的结论继续有效：

- 任何微信用户都可创建活动，不引入前置审核、白名单或邀请制；
- 不提供公共流量推荐与算法分发，发现页不做个性化排序；
- 不承诺救援，不做在线支付、保险、发票与合同；
- 领队认证标识、能力标签、历史评价仍留在 V2。

## 4. 隐私投影：发现页做减法

发现页**不复用**活动详情投影，改为独立的窄投影 `discoverView`：

| 字段 | 是否返回 | 原因 |
|---|---|---|
| `ownerId` | **不返回** | 原始 openid 不应出现在对任意用户可见的列表里；改为返回布尔 `owner` 供客户端标注「我组织的」 |
| `pickupPoints`（含地址与坐标） | **不返回** | 集合点是参与者才需要的信息，且含精确坐标 |
| 路线、装备、费用、取消说明、容量、已确认人数 | 返回 | 构成「是否值得报名」的判断依据，且本就是有意公开的内容 |
| 报名者名单、手机号、位置、紧急联系人 | 不返回 | 始终不进入该投影 |

报名所需的集合点信息仍通过活动详情页按原有权限模型提供，发现页的收敛不损失任何功能。

## 5. 数据与存量兼容

- `Activity` 新增 `publishedAt`，声明为**可选**字段。schema 校验是严格的（不允许缺键），因此可选声明是存量数据不失效的前提。
- `activity.publish` 写入 `publishedAt = context.now`。
- `ActivityInput` 显式排除 `publishedAt`，避免客户端在创建或编辑时伪造发布时间。
- `activity.copy` 显式清除 `publishedAt`，复制出的草稿不得继承来源活动的发布时间。
- 存量已发布活动没有 `publishedAt`：**仍然可被发现**，排序时视为最旧，落在列表末尾。无需数据迁移脚本。

## 6. 风险与控制

| 风险 | 当前控制 | 状态 |
|---|---|---|
| 用户误以为创建者具备专业资质 | 发现页顶部固定说明「这些活动由个人发起」，要求以活动说明为准、自行评估适配性；不使用「认证」「保障」类表述 | 已实现 |
| 集合点与身份信息外泄 | 窄投影不返回 openid 与集合点坐标 | 已实现 |
| 全量读取的性能放大 | 既有设计本就每次 `read` 全量加载；发现页单次上限 50 条，搜索输入 300ms 防抖 | 已实现（架构级性能债见第 8 节） |
| 虚假活动、骚扰、恶意分享 | 仅有文案提示；**无举报入口、无创建频率限制、无风控** | **未实现** |

## 7. 明确记录的欠账

ADR 0001 第 2 节要求详情页展示「未认证领队」标识，第 4.2 节要求提供举报入口。两者在代码中**均未实现**（全仓检索 `未认证` / `举报` / `投诉` 无命中）。在本 ADR 提前开放发现之后，这三项成为优先级最高的欠账：

1. 领队资质标识（至少「未认证」这一档）；
2. 举报入口与平台下架能力；
3. 创建频率限制与基础风控。

## 8. 后续演进

- **V2**：补齐第 7 节三项；发现页增加按出发时间、名额、路线强度的筛选。
- **V3**：与 `V3-开放的户外路线基础设施.md` 第 5.1 节「公开活动发现」合并，扩展到俱乐部主页、服务商网络与智能推荐，并治理出更完整的准入、评价、投诉与退出机制。
- **架构债**：`store.js` 每次请求全量加载所有集合，活动列表性能是 O(全库) 而非 O(分页)。发现页把这个问题从「熟人量级」推到「陌生人量级」，应在 V2 随数据量增长一并处理。
