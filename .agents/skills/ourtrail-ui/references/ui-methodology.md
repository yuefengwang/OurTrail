# OurTrail UI/UX 设计方法论

服务对象：M1 Design/Build 与 M2 Improve/Refactor。
用法：本文件给的是**判据**，不是模板。统一的是设计语言与行为原则，不是"所有页面长同一个样"。任何一条与具体页面的任务冲突时，按 SKILL.md §1 的优先级裁决并登记。

## 0. 先定这一屏的唯一主任务

写不出"用户在这页要完成的唯一一件事"之前，不要开写样式。

- 判据：一句话、动词开头、指向可观察结果。正面例：`workspace`「用同一份名单完成审核、分车、签到、收尾」；`route-edit`「把这条路线存下来」。
  反例（等于没定）：「展示活动信息」「管理路线」。
- 主任务决定**首屏必须回答的四问**（`utils/journey.js` 是这套问答的唯一翻译层，见铁律 22）：我在哪一步 / 现在什么状态 / 为什么 / 下一步做什么。四问齐备是 `tools/journey-test.js` 的实测判据，页面只是插值。
- 定不出来 ⇒ 不要猜。**在改动清单里写明"主任务待负责人确认"并给出两个候选及其结构差异**，这是 M2 的合法产出；擅自选一个并把另一条抹掉，才是问题。

## 1. 信息层级与阅读顺序

- **首屏折叠线内必须出现主任务的推进路径**（入口、状态、或唯一主操作）。把结论性内容压到折叠线以下＝层级颠倒。
- 层级靠**字重与颜色**建立，不靠放大字号（正文 400/500、强调 600、700 仅 `.page-title`）。这是可核的：字号一档跳变而字重不变，通常是无信息量的装饰性强调。
- **按"有没有变化"分层，而不是把所有可读到的东西同权重铺出来**。同一条重复语句在多行重印、没有变化的行与有变化的行同权重＝噪声（本项目天气线为此专门减过权重，见 SYNC.md 天气轮与 `docs/weather-ux/weather-ux-design.md:23` 的"禁彩色卡片堆"）。
- 三层不混排（`docs/weather-ux/weather-ux-design.md:58-59`）：**L1 客观事实 / L2 分析判读 / L3 建议**。L2 不混进 L1 区块，L3 不独立成卡，跨层只允许一个跳转锚点。任何"数据 + 判断 + 建议"同屏的页面都适用，不只天气。
- 阅读节奏：`.stack` 16px 是纵向基准；一个视觉块内部靠 `.section-head`（标题 + 右侧 `.section-sub`）分段，而不是靠再套一层卡片。想"再包一张卡"之前先问：这是新的一段信息，还是同一段的延续？后者一律用标题与留白解决。

## 2. 结构选型（不是默认套 `.card`）

| 这屏在做什么 | 首选结构 | 反模式 |
|---|---|---|
| 多个同类条目待扫视/操作 | `.list-row`（+ `.list-main`/`.list-sub`）或业务卡组件 | 每条目一张 `.card`，卡内再套卡 |
| 单对象详情（一条活动/一条路线） | `.section-head` 分段 + 段内 `.card` 一到两张 | 同级 8–11 张卡竖排（实测 `me.wxml` 9 张、`route.wxml` 8 张、`editor.wxml` 11 张且 `:188/:205/:256/:271` 卡中嵌卡） |
| 输入为主 | `<form-field>` + `.form-actions`，一屏一件事，多步用 `step` | 一个大长表单不分步；标签在屏内重复出现 |
| 需要"先看全局再决定" | `.hero`/`.metrics` 顶栏 + `.segmented` 分区 + 面板 | 用文字列表复述指标（`.metrics/.metric` 已存在且 hero 内自动反白） |
| 时间/数量随维度变化的数据 | 自绘图表（`<meteogram>`/`<space-time>`，几何在 `layout.js` sidecar） | 把时序表写成 `label: value` 罗列 |
| 破坏性动作 | 入口用文字/次要样式，红实心只在 `overlay kind="dialog"` 内 | 页面主体直接放 `.button danger block`（实测 `route.wxml:189`、`lab.wxml:76`） |
| 临时选择/筛选/批量 | `overlay kind="sheet"` + 弹层内主按钮 | 把选项摊成正文一长列 |

选择顺序：**先找现有类 → 再找现有组件 → 再考虑扩展组件 → 最后才新建**。新建全局类前必须全局搜类名确认无等价物（SKILL.md §3 前置 1）。

## 3. 信息过载 / 卡片堆叠 / 视觉噪声的可判信号

不要写"这里太乱"。用可指认的信号，一条一个 `file:line`：

1. 同屏同级容器数 ≥5 且无 `hero`/`section`/`card` 层级差 ⇒ 层级缺失。
2. 同一句话在多行重印（每行都重复"点击可…"这类）⇒ 应上提为一次区块说明。
3. `label：value` 逐行罗列 ≥3 行同构 ⇒ 标签合并进值或降为次级文本（实测 `route.wxml:95` 一行塞五标量；`activity.wxml:291-293` 与 `roster-panel.wxml:114-116` 三行同构且重复两处）。
4. 容器同时有边框 **和** 底色差 ⇒ 去边框（`.card` 已带边框，页面内别再叠 `background`）。
5. 无功能的筛选项/分段控件在空态下仍显示 ⇒ 空态里隐藏它们。
6. 一行里出现两种以上颜色的强调，且不承载语义 ⇒ 色相被当装饰用，违反"文字承载语义"。
7. 数字未用 `.tabular` 导致列对不齐（时间/里程/人数）⇒ 结构性问题，不是观感建议。

**不误判**：密集不等于过载。名单/分车/工作台这类页的高信息量是任务本身要求的；判过载要看**同一层里是否有可分组或可降权的重复单元**，不是看条目总数。天气页结论卡多但每张承载一个独立判读，按 #1 有 `section-head` 分段就不算层级缺失。

## 4. 操作设计：主 / 次 / 危险

- 主按钮预算＝这一屏唯一推进动作（SKILL.md #7）。例外必须能指认互斥证据：`wx:if`/`wx:else` 成对、`step` 分步、弹层内部。
- 批量动作（全部通过/全部导出/批量取消）一律次要样式；主样式只出现在确认弹窗内。
- 危险操作三件套：二次确认 + 影响范围自陈 + 需要处必填原因。正面样本 `route.wxml:188`（删除前点名影响）。
- **不可逆动作不许藏在无文案的图标里**；图标必须挨着文字或带可读 label。
- 按钮禁用要三层一致：`.disabled` + `bindtap` 置空 + handler 内守卫。只置灰不置空＝"看着能点、点了没反应"（铁律 21 记录过 `bindtap="{{cond ? '' : 'onX'}}"` 这类实例）。
- 提交期间 `busy` 必须挡住重复触发；成功后要么重读要么离开，不许停在旧数据上（`dispatchAndSync` 已经做了重读，见 #6）。

## 5. 状态设计：六态与"看不见不能等于没事"

每屏至少想清楚这六态：`loading`（骨架）/ `empty` / `error` / `denied` / `offline` / `submitting(busy)`。

- 一律走 `<status-panel>`（契约源自原型 `StatusPanel.tsx:5-8`：`kind` 五值 `empty|loading|error|denied|offline` :5、`title` :6、**`detail` 必填** :7、`action` 可选 :8）。empty 的 detail 必须回答"为什么空 + 下一步做什么"，正面样本 `route.wxml:96-97`「这个节点没有坐标，查不了天气」「超出了 14 天预报窗口，临近再查」。
- **denied 态必须给出路**（`tools/journey-graph-test.js` 常驻查"denied 无出口"）。一屏红字没有下一步 = 缺陷，不是风格问题。
- 判不出 ≠ 否定。天气线的结论：**弃权（unknown）必须仍然出现并说明缺什么，只有确证不成立（excluded）才沉默**（`docs/weather-ux/qa/v2-silence-gate-2026-10-10/README.md:29-47`）。任何"数据不全就隐藏"的设计都会把"没数据"冒充成"没有"。
- **减卡/减话必须点名被减项**（同报告 `:97,:101`，铁律 33④）。少内容却不能让用户分清"今天没戏"和"工具坏了"，就是失败的设计。
- 降级必须自陈时效与来源：兜底数据显示时附"截至 X 时"，模型估算值追加"（模型估算）"，被裁切的视图必须说明"窗外还有…"（铁律 27、25③）。
- 状态文案不许甩锅、不许英文、不许把内部错误码直接印出来（`utils/journey.js` 的 `CODE_TITLES` 保证每个错误码有人话）。

## 6. 跨页面流程连续性

- 页面图必须闭合：每页要么在 tabBar/有入口，要么登记进 `DEV_ONLY` 并写明理由；不许"有入口没返回路径"、不许"denied 无出口"（`tools/journey-graph-test.js`，铁律 22）。
- 同一状态在两处显示必须同源：文案出自 `format.js`/`journey.js`，判据出自服务端投影，页面只插值。跨页看到互相打脸的状态词就是这条烂了（`roster-panel` 旧 `STATUS_OPTIONS`、`workspace` 旧 `SUBTITLES` 都烂过一次）。
- 跳转带最小可辨识参数；超大数据（如 168 小时图表）走单例 store（`chart-store.js`）而不是塞 `navigateTo` query。
- 流程改动后自查：从入口进去，能否在 ≤2 步内回到用户刚来的地方；每步的"下一步"是否由 `journey.js` 给出。

## 7. 专项形态要点

**表单**：一屏一组；`<form-field>` 的 hint 写格式、error 写怎么修；正确键盘类型（number/digit/nickname）；失焦自动保存必须成功失败都有反馈（toast + 状态行）。`editor` 的草稿优先于服务端数据（BUG-C2 已登记），改编辑类页面时先看 `SYNC.md` 别踩回来。
**弹层**：`<overlay kind="sheet|dialog">`，内容放 `.stack`，超高走 `scroll-view`；**关闭态必须不可命中**（`platform-pitfalls.md` §4）；弹层里的主按钮单独计预算。
**筛选/分段**：`.segmented > .seg(.on)`；选中态与非选中态对比 ≥3:1；空态下无意义项隐藏；筛选后结果数必须可见。
**列表**：行高由触控目标决定（≥44px 主点击）；`<person-row>` 头像回退首字；行内动作 ≤1 个，多于一个收进 sheet；长文本 `word-break` 或省略，不许撑破。
**工作台**：顶部 `.metrics` + `.segmented` 分区 + 自取数面板；面板间写入必须靠 `sync-key`/`written` 事件失效（`miniprogram/AGENTS.md`），否则下一个命令必撞 CAS CONFLICT——这是 UI 问题不是后端问题。

## 8. 可读性与适配（长文本 / 窄屏 / 缩放 / 对比度 / 触控）

- 窄屏基准三档 **375 / 390 / 414**（天气线的实测判据宽度）。标签重叠、图例挤行、按钮换行只在其中一档出现也算缺陷——天气线用 SVG 图元几何在 `meteogram-readability-test.js` 逐档判。
- 长文本：姓名/地址/备注必须 `word-break` 或显式省略；不许用 `white-space: nowrap` 把内容顶出容器。
- 对比度：正文对 ≥4.5:1，输入框/勾选框描边 ≥3:1；`--muted` #5F6E66 已是 4.6:1，**不要再调淡**。色块上的文字用 `layout.js` 的 `inkOn()` 判亮暗（`lum>0.55` 走深墨，`components/meteogram/layout.js:106-113`），别写死白字——#D6A33C 上白字只有约 1.9:1。
- 触控：主目标 ≥44px（`--touch-target`），主操作 48px；相邻可点目标之间留出可辨间隔；密集行内控件按 SKILL.md #8 的 R 档处理并写明豁免理由。
- 文字放大（微信内可设）：任何"一行写完"的设计都要在放大后仍成立——固定宽度容器内的多段标量（如 `route.wxml:95`）是典型断裂点。无法静态判的记 E3，需要真机放大验证。
- 数字/时间用 `.tabular`；时间统一北京时间（`utils/format.js`）。里程爬升为 0 时不印「0km/0m」，缺就不印（这是 `completeness` 派生后的既有约定，见 SYNC.md 快速创建轮）。

## 9. 复用 / 扩展 / 新建组件的判据

- **复用**：`design-system.md` 组件清单里已有等价物，且 slot/props 覆盖得住。
- **扩展**：同一交互契约、只是数据多一类 ⇒ 加属性/变体，不改已有语义（例：`field-panel` 的 `perspective` 同时服务 workspace 与 staff）。
- **新建组件**：≥2 个页面有同一契约的稳定需求，且它不是"一段样式"而是"一份行为"。只为单页的视觉 ⇒ 写页面 wxss，不要往 `app.wxss` 塞全局类。
- 新组件必须过：`usingComponents` 在**页面 json** 注册（根路径绝对）· `options` 只写一次并含 `styleIsolation`（引用全局类时）· 具名 slot 必须声明 `multipleSlots: true`（否则内容被静默丢弃且 data 一切正常）· 需要被 Node 测的几何/配色 ⇒ 抽 `layout.js` sidecar，不要在测试里复刻组件计算（铁律 11）。
- 纯函数 util 不许碰 `wx.*`（除 `api.js`/`draft.js`），否则静默脱离 Node 覆盖（`miniprogram/utils/AGENTS.md:3,88`）。

## 10. 质量标准表（每维：什么问题 / 别误判成问题 / 代码证据 / 何时必须截图或交互 / 严重度起点）

| 维度 | 什么问题 | 别误判 | 代码证据 | 何时需 M4 | 起点严重度 |
|---|---|---|---|---|---|
| 信息架构与任务优先级 | 主任务写不出；首屏无推进路径；四问缺一 | 条目多但每条独立承载判读 | `journey.js` 出口、页面 wxml 顺序、`this.setData` 字段名 | 折叠线归属需真机视口读数 | HIGH |
| 视觉层级与阅读节奏 | 靠字号而非字重；同权重铺陈；L1/L2/L3 混排 | 有 `section-head` 分段的长页 | 类名与选择器（`grep` 字重/字号）| 层级观感只能靠截图判，且必须标 E3 | MEDIUM |
| 布局留白与内容密度 | §3 七条信号任一 | 密集是任务要求的工作台/名单 | wxml 行号区间 + 容器计数 | 溢出/挤压/换行必须截图 | MEDIUM |
| 组件一致性与适度差异化 | 同义控件两处不同实现；单页视觉塞进全局类 | 有理由的变体（`perspective`、`kind`）| `usingComponents` 对照、`app.wxss` 类清单 | 降级外观（如 map 圆角失效）需截图 | MEDIUM |
| 交互可发现性与状态反馈 | hover 缺失、只置灰不置空、`busy` 可重复触发 | 图标+文字已足够显式 | `bind*` 与 handler 对照（`check-handlers.js` 只到 handler 存在性）| **必须真机 tap + 后果** | HIGH |
| 错误恢复与危险操作 | 静默失败、无出路 denied、红实心裸露、不可逆无确认 | 确认弹窗里的红实心 | 四态分支 + `.danger` 位置 | 真实故障路径需注入或断网 | HIGH |
| 可访问性与长文本 | 对比不足、白字压浅底、nowrap 溢出、触控目标过小、放大后断裂 | `var(--x,#fallback)` 不是发明色；行内小控件可按 R 档豁免 | 色值配对计算、`--touch-target` 引用、宽度三档 | 放大/窄屏真机档 | MEDIUM |
| 跨页一致性与完整旅程 | 状态词两处不同源、有入口无返回、denied 无出口、跨页打脸 | 已登记 `DEV_ONLY` 的工具页 | `journey-graph-test.js` 输出、`format.js` 常量 | 多步链路建议真机走一遍 | HIGH |
| 微信平台实现风险 | 违反 P 类（`apply-shared`、tabBar 自包含、底部留白、canvas 不能取 var、关闭态可命中） | meteogram 全类本地不需 apply-shared；tab-bar 字面量是允许例外 | 源码即可判 | 只有像素才能证明"真的没生效" | BLOCKER（线上表现） |
| 可验证性与回归风险 | 结论无可指认证据；静态过就宣称正常；未执行检查标 PASS；无阳性对照 | 记 INCONCLUSIVE 是合格产出，不是失败 | `file:line` + 报告字段 + 门命令与退出码 | 结构性改动后一律 | HIGH |

> 严重度是**起点**，不是终点：有 E1 证据支持"用户必然卡住/必然点不到"可升 HIGH/BLOCKER；只有 E3 且未验证 ⇒ 状态保持 OPEN 并写明需要什么证据。分类不许降级汇报（同一发现别为了"看着好过"从 HIGH 写成 MEDIUM）。
