# UI/UX 审计与验证：证据分级、严重度、误判防线

服务对象：M3 Audit（只读）与 M4 Visual/Runtime Verification。核心一条：**结论的强度不能超过证据的档位**，且四类手段（静态代码审计 / 截图审查 / 自动化点击 / 真机人工）不可混为同一种证据。

## 0. 规范与代码不一致时：先判 STALE 还是 DEBT

本 skill 的条目不是"永远对"。2026-10-14 实测就有两类不一致，处理方式完全不同：

| 情形 | 判据 | 本仓实例 |
|---|---|---|
| **文档 STALE**（规则本身已不成立） | 代码里找不到该规则指向的对象；或规则引用的类/字段/文件已不存在；或计数对不上 | `design-system.md` 曾登记 `.sky-card/.sky-title/.sky-text` ⇒ 全库 NOT_FOUND，真实类是 `.cond-card/.cond-pheno/.cond-silent/.sky-look*` 且定义在**页面级** `weather.wxss`；根 `AGENTS.md` 写「33 tokens」而 `app.wxss` 实测 40 个自定义属性（29 色 + 11 数值） |
| **代码 DEBT**（规则仍成立，现状违反） | 规则指向的对象存在、可判、且现有实现里有合规同类作为对照 | 「不发明新色值」：`app.wxss` token 齐全，`home/discover/weather/activity/overlay` 5 个活文件仍有字面量色值，而 `me.wxss` 4 处全是 `var(--x,#fallback)` 兜底（合规） ⇒ 前者是债，后者不是 |
| **规则过宽**（该收窄适用范围而不是判代码错） | 存在成批"看起来违反但其实合理"的样本 | 「所有组件必须 apply-shared」⇒ `meteogram` 全部类本地定义，不需要；「所有提交用 dispatchAndSync」⇒ `signup.js:378` 的 CAS 链是合规例外 |

**四问顺序**：①规则指向的东西还在吗（不在＝STALE）②有没有合规对照（有＝倾向 DEBT）③违反是不是设计上有理由（是＝规则过宽，收窄规则）④我用的这把尺能产生差异吗（尺不敏感＝不能报"0 命中"也不能报"全违反"）。

被判 STALE 的原文**不删**，加前向指针写明"何时被什么证据证伪"（沿用天气线铁律 29③ 的翻案链做法）。

## 1. 证据四档

| 档 | 名称 | 能成立什么结论 | 不能成立什么 |
|---|---|---|---|
| **E1** | 代码直接证实 | 结构/注册/引用/互斥/静态可判的缺失。例：某页 wxml 未引用 `status-panel`、组件缺 `options`、同一 `.form-actions` 里两个无条件 `.button primary` | 页面"渲染坏了"、用户"看不到" |
| **E2** | 由实现强烈推断 | 必须写出推断链（A 处赋值 → B 处条件 → 屏上只剩 C）。适合"数据对但渲染可能不对"的**风险**判断 | 任何"实测已发生"的表述；只许写"会/可能"，不许写"已" |
| **E3** | 需真实渲染或交互验证 | 只有拿到截图/DOM 读数/tap 后果后才升级成立。像素层证据要求：截图存在 + bundle 新鲜 + 门槛链断言通过 | 不许用 `page.data()` 读数代替像素（铁律 32⑥a）；不许用元素数量代替对象状态（铁律 21） |
| **E4** | 观感主张（不可证） | 明确标注为建议，如"这里显得挤""配色偏冷"。可以提，但不得计入缺陷数、不得定严重度 | 不得写成发现；不得据此立项重构 |

状态词只有四个合法值：**VERIFIED / UNVERIFIED / INCONCLUSIVE / OPEN**。没跑的检查写 UNVERIFIED 或 NOT_RUN，绝不写"通过"。跑不动（无开发者工具、会话僵死）写 INCONCLUSIVE 或 ENV-ABORT，不写产品红。

## 2. 严重度

`BLOCKER`（线上必现不可用/点不动/数据错印）> `HIGH`（主任务受阻或状态误导）> `MEDIUM`（层级、密度、一致性损伤）> `LOW`（打磨项）。

- 起点见 `ui-methodology.md` §10 最后一列；升降级必须写理由与新增证据档。
- **规范偏离与体验缺陷分开记账**：违反 S/R 类但拿不出用户受损的路径 ⇒ 记"规范偏离 MEDIUM/LOW"，不许写 HIGH；反之，没违反任何条文但主任务走不通 ⇒ 照样 HIGH（本 skill 不是合规白名单）。
- 分类不许降级汇报，也不许合并成一条模糊的"待优化"。
- P 类平台规则违反：起点 BLOCKER 的前提是"能指出触发条件"；只有代码差异而无渲染证据时，写 E1 + HIGH + 待 E3 复现。

## 3. 误判防线（每条都是实测撞过的）

1. `var(--x, #literal)` 兜底**不是**发明色值；注释里的 hex 不算使用（`space-time.wxss`、`meteogram.wxss` 各 1 处是注释假阳）。
2. 两个 `.button primary` 若被 `wx:if`/`wx:else`、`step` 或不同 overlay 隔开 ⇒ 不计同屏违例；**判不出运行时组合就降 E2/E3**（实测 `activity.wxml:231-232`、`workspace.wxml:70+91` 属这一类）。
3. 确认弹窗内的红实心 `.danger` 是规范允许的，不是"危险色裸露"。
4. 纯静态页（`staff`/`privacy`/`cloud-field-poc`）没有四态分支是合理的；`weather-hub` 有数据源却裸文本 ⇒ 才是 DEBT。
5. 死代码不参与审计：`components/privacy-popup/`（未注册）里的 7 处发明色、无 `options` 都不是问题；但**新代码引用它会直接是 BLOCKER**（`check.js` 步骤 5b 会红）。
6. `app.json` 无全局 `usingComponents`，"组件没在 app.json 注册"不是缺陷——注册在**页面 json**。
7. 元素数量不能证明状态：`planOpen=false` 时 `.list-row` 照样存在（铁律 21 的实测实例）。
8. 假绿夹具：注入载荷缺字段会让分支根本走不到（天气线 P7 因"缺读数"用例只铺一行 `00:00` 却去查 `06:40` 而长期全绿）。**审计里"某分支不执行"的结论必须先证那分支可达。**
9. `tools/check.js` 通过不代表合规。2026-10-17 复量后的真实边界：平台/作用域类已有常驻门（apply-shared 缺失、`options` 同名键、具名 slot 缺 `multipleSlots`、裸事件属性名、页尾留白↔tabBar 身份、WXSS 特性黑名单、sticky 无偏移、同一条选择器文本双写、类定义作用域）；**仍然没有全仓门**的是硬编码色值与新 token 登记（只在批次写入集套件里查）、四态覆盖、44px 触控尺寸、以及需要像素/运行时证据的 platform-pitfalls §4/§14。审计结论里写"已过门禁"之前，先说清是哪一道门、覆盖到哪个范围。
10. 门禁夹具里的绝对日期是时间引信（`e2e-test.js` 曾把 `deadlineAt` 写死导致过点即红）；引用别人结论前先确认取证的尺与生产实现**等价**（铁律 29①：不等价的探针会同时造出假差异和假否定）。

## 4. 只读审计报告的最小字段

每条发现必须齐这七项，缺项就写 `NOT_MEASURED` 而不是省略：

```
[N-01] 标题（一句，动词指向用户后果）
证据档: E1 | 严重度: HIGH | 状态: VERIFIED / OPEN / INCONCLUSIVE
位置: miniprogram/pages/x/x.wxml:123（区间写 :123-140）
判据: 违反 SKILL.md §3 #N 或 ui-methodology §X 第 N 条信号（或"不违反任何条文但…"）
事实: 实测到的东西（计数/类名/条件），不是形容词
推断链: E2/E3 必填——从哪个赋值到哪个条件到屏上会怎样
所需补充证据: 缺哪张截图/哪次 tap/哪个视口宽度才能定论
```

分区闭合自查：发现的条数要能对上口径（例如"同屏 9 张卡"要写清 `:9/:63/:74/:99/:110/:142/:168/:181/:194` 九个行号，能被复核）。

## 5. 视觉/运行时验证记录模板（M4 必填）

```
环境: 微信开发者工具 <版本> / 基础库 3.8.12 / WebView 渲染（skylineRenderEnable=false）/ 视口 375|390|414 / 深色模式不支持（app.json 无 darkmode）
页面: /pages/x/x?query   数据来源: 真实云端 | 注入(必须给载荷形状与生产字段对照)
有效性门: bundle 新鲜=<新文案/探针>   门槛链=<逐项读数>   缓存=<updatedAt 各不相同 + 两例读数互不相同>
步骤: 1) … 2) tap 目标 → 观测后果（自动化里 UI PASS 必须由一次真实操作+后果构成）
读数: DOM 文本 / 组件 data / 截图路径
结论: 哪些是像素证实的，哪些只是 data 证实的
```

落盘约定：人工 QA 证据放 `docs/<线>/qa/<轮次>/device/`，含 `readings.json`；被作废的截图**移入 `device/invalid/` 不删除**（保留失败链）。自动化截图默认落在仓库外临时目录，且 `tools/e2e-ui-test.js` 明文"仅作 Evidence，不参与任何判定"⇒ **它不是判据**，别把它当视觉验证通过的证据。

## 8. 多 Agent 审计的可复核性

- 每个 Agent 的发现表里必须自带**取证命令或行号**，使另一 Agent 能独立复现；复现不了标 UNVERIFIED 并回抛。
- 去重键＝`file:line` + 判据条目；同位置不同判据保留两条。
- 冲突保留原样列出双方主张与证据档，交裁决；不许折中、不许静默丢弃、不许"以多数票为准"。
- 本 skill 自身也在被审计范围内：若某轮审计证明某条规则 STALE，按 §0 加前向指针修正条目并登记该轮报告，而不是让代码迁就旧文。
